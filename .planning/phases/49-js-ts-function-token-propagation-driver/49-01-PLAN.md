## Trust Boundaries

| Boundary | Risk | Mitigation |
|----------|------|------------|
| `.polint.toml` `[solver.js]` values | A repo config typo could disable propagation or force pathological work. | Treat zero as default, keep caps finite, and fold values into cache digests. |
| TS source-derived stable keys | Malformed or unsupported source forms could be mistaken for callable identities. | Compose from existing TS inventory and semantic graph identities only; leave unsupported forms unresolved. |

## STRIDE Notes

- Tampering: cache keys include JS token budget knobs so changed caps cannot reuse stale solver output.
- Denial of service: positive finite caps and zero fallback prevent unbounded token propagation and accidental self-disable.
- Information disclosure: all new fields remain crate-private and do not expose source text or new public SDK facts.
</threat_model>
