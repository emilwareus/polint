    - `fn extract_literals_and_jsx(...)`
    - `fn walk_statement_for_literals(...)`
    - `fn walk_expression_for_literals(...)`

    - `fn jsx_attribute_value(...) -> Option<String>`

    String literals:
    - For `Expression::StringLiteral(literal)`, push `StringLiteralFact { value: literal.value.to_string(), span: span_from_oxc(file_id, source, literal.span), language }`.
    - For `Expression::TemplateLiteral(template)`, when `template.expressions.is_empty()`, join all cooked quasi values when present, otherwise raw quasi values, and push one exact `StringLiteralFact`.
    - For dynamic templates with expressions, push each non-empty static quasi as its own `StringLiteralFact` using the quasi span. Do not concatenate expressions or create a synthetic full template value.
    - For `Expression::TaggedTemplateExpression(tagged)`, process `tagged.quasi` the same way as `TemplateLiteral`.

    JSX attributes:
    - Walk `Expression::JSXElement(element)` and nested JSX children.
    - For each `JSXAttributeItem::Attribute(attribute)`, derive names from `JSXAttributeName::Identifier` and namespaced names as `namespace:name`.
    - Values: `JSXAttributeValue::StringLiteral(literal)` uses `literal.value.to_string()`. `JSXAttributeValue::ExpressionContainer(container)` records a value only for stable simple expressions: identifier names, string literals, numeric literals, and static template literals with no expressions. Boolean attributes with no value record `None`. Spread attributes do not create `JsxAttributeFact`.

    Keep facts deterministic by walking program statements in source order and attributes in opening-element order. Do not add a CSS parser.
  </action>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Tampering | string/template extraction | mitigate | Dynamic templates are not concatenated into exact values; tests assert no synthetic expression-containing value. |
| T-05-03-02 | Spoofing | raw color literal facts | accept | Facts report source syntax only and do not claim CSS semantic validation or design-token authority. |
| T-05-03-03 | Denial of Service | recursive expression/statement traversal | mitigate | Traverse the bounded parsed AST and avoid repeated whole-source scans for literals and complexity. |
