<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Oxc AST to core facts | Untrusted repository syntax is transformed into shared facts used by rules and graph helpers. |
| TS adapter to SDK-facing core | New class facts and capabilities become public query surface for later rule authors. |
| Component heuristic to diagnostics | Approximate component facts can influence rule diagnostics and user interpretation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Tampering | `AnalysisDb::push_ts_class` and TS traversal | mitigate | Preserve append-only insertion order and assert exact class/function/import order in unit tests. |
| T-05-02-02 | Spoofing | component detection | mitigate | Use the code phrase `syntax-level component heuristic` and avoid exact React discovery claims. |
| T-05-02-03 | Denial of Service | recursive AST call extraction | mitigate | Traverse Oxc AST nodes once per function/class body and sort/dedupe bounded call vectors per function. |
| T-05-02-04 | Elevation of Privilege | new `Capabilities::ts_classes` | accept | Capabilities expose local fact availability only; they do not grant file, network, or process privileges. |
</threat_model>
