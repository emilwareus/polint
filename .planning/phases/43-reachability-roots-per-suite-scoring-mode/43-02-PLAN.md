<objective>
Add the required `scoring_mode` field to `SuiteManifest` (with the closed `ScoringMode` enum, kebab-case wire strings, structural + explicit gate-fails-if-missing, and a negative test), update all four committed suite manifests, compute the reachable set by BFS/DFS over the v1.2 direct-call edge set, emit `CallReachabilityFact` marking (composition, not mutation of `analysis::calls`), and add the mode-aware scoring filter to the eval runner/metrics path.

Purpose: REACH-02. The oracle each suite was built against expects a specific scoring mode — `oracle-rta` reports reachable-only edges, Jelly enumerates whole-module. Getting these backwards silently tanks one suite's recall. Marking unreachable calls as facts-but-outside-the-graph (rather than dropping them) preserves the v1.2 composition discipline that downstream solver phases rely on.
Output: `ScoringMode` + `scoring_mode` field, 4 updated suite TOMLs, `traverse.rs` reachable-set + `CallReachabilityFact`, and the mode-aware scoring filter.

|----------|-------------|
| suite manifest TOML -> ScoringMode | Untrusted suite-manifest `scoring_mode` values cross into the eval scoring path. An invalid value must be rejected at parse/validate time, not silently coerced to a default mode (which could mis-score a suite). |
| reachability marking -> eval scoring | The mode-aware filter reads `CallReachabilityFact.in_reachable_graph` by stable-key join; a missing/forged marking must not silently include or exclude edges. |
