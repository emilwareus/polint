    Create analysis/entrypoints/recognizers_ts.rs with:

    pub(crate) fn recognize_ts_entrypoints(db: &AnalysisDb) -> TsRecognizerOutput
    where TsRecognizerOutput has entrypoints: Vec of EntrypointFact, unresolved: Vec of UnresolvedFrameworkFact.

    The function should:

    1. Build lookup maps: files by id, functions by id, imports by file, call sites, symbols, references.

    2. Detect TS/JS framework imports per file:
       - "express" -> framework_id "ts.express"
       - "@modelcontextprotocol/sdk" or any path starting with "@modelcontextprotocol/" -> framework_id "ts.mcp_sdk"
       - "commander" -> framework_id "ts.commander"
       - "yargs" -> framework_id "ts.yargs"
       - "jest", "vitest", "@jest/globals" -> framework_id "ts.jest" or "ts.vitest"
       - "mocha" -> framework_id "ts.mocha"

    3. For Express (per D-07): scan call sites in files with "express" import. Match patterns:
       - app.get, app.post, app.put, app.delete, app.patch, app.options, app.head calls: extract HTTP method from call name, route path from first string literal argument, handler function from last argument. Emit EntrypointFact with kind HttpRoute, framework_id "ts.express", trigger_metadata.method (GET, POST, etc.), trigger_metadata.path from literal.
       - app.use calls: emit EntrypointFact with kind HttpMiddleware.
       - Router() creation followed by router.get/post/etc.: same pattern with Router prefix.
       - app.route("/path").get(handler).post(handler): route chain — emit one entrypoint per chained method.
       - If express import detected but no matching registration patterns, emit UnresolvedFrameworkFact.
       - Precision is Heuristic per D-07.

    4. For MCP TypeScript SDK (per D-07): scan call sites in files with MCP SDK import. Match patterns:
       - server.tool("name", handler): emit EntrypointFact with kind McpTool, trigger_metadata.tool_name from first literal argument.
       - server.resource("name", handler) or server.resource(template, handler): emit EntrypointFact with kind McpResource, trigger_metadata.tool_name from literal.
       - server.prompt("name", handler): emit EntrypointFact with kind McpPrompt, trigger_metadata.tool_name from literal.
       - If MCP SDK import detected but no tool/resource/prompt registrations found, emit UnresolvedFrameworkFact.
       - Precision is Heuristic.

    5. For test frameworks (per D-08): scan call sites for describe, it, test function calls in files that import jest, vitest, mocha, or @jest/globals. Emit EntrypointFact with kind Test, framework_id "ts.jest"/"ts.vitest"/"ts.mocha", trigger_metadata.test_name from first literal argument. Precision is SetupAware (depends on test runner being configured).

    6. For CLI frameworks (per D-09): scan call sites for:
       - commander: program.command("name"), .action(handler) patterns. Emit EntrypointFact with kind CliCommand, framework_id "ts.commander".
       - yargs: yargs.command("name", ...) patterns. Emit EntrypointFact with kind CliCommand, framework_id "ts.yargs".
       - Precision is Conservative per D-09.

    7. For unrecognized TS/JS framework imports (per D-10): if a TS/JS file imports a package containing "fastify", "koa", "hapi", "nest", "@nestjs", "next", "nuxt", "remix", "sveltekit", "astro" but it is not Express or MCP SDK, emit UnresolvedFrameworkFact with reason UnsupportedFrameworkVersion.

    All stable keys use semantic_stable_key(FactFamily::Entrypoint, ...) with labeled parts. provider_id is "polint.entrypoints".

    Sort output by stable key at the end.

    Add a #[cfg(test)] module with tests covering: Express app.get recognition, MCP server.tool recognition, jest/vitest test() recognition, commander recognition, unresolved framework detection.
