    Create analysis/entrypoints/recognizers_go.rs with:

    pub(crate) fn recognize_go_entrypoints(db: &AnalysisDb) -> GoRecognizerOutput
    where GoRecognizerOutput has entrypoints: Vec of EntrypointFact, unresolved: Vec of UnresolvedFrameworkFact.

    The function should:

    1. Build lookup maps: files by id, functions by id, imports by file, call sites from db.call_sites(), symbols and references for binding resolution.

    2. Detect Go framework imports per file by scanning import module_path values:
       - "net/http" -> framework_id "go.net_http"
       - "github.com/go-chi/chi" or "github.com/go-chi/chi/v5" -> framework_id "go.chi"
       - "github.com/spf13/cobra" -> framework_id "go.cobra"
       - "testing" in files ending with _test.go -> framework_id "go.testing"

    3. For net/http: scan call sites in files with "net/http" import. Match callee shapes:
       - "http.HandleFunc" call with 2 arguments: extract route path from first arg (string literal if available), handler from second arg (function reference). Emit EntrypointFact with kind HttpRoute, framework_id "go.net_http", trigger_metadata.path from literal, trigger_metadata.method None (HandleFunc registers all methods), precision Heuristic, provenance NativeRecognizer, status Resolved.
       - "http.Handle" call: same pattern but handler is an interface implementation.
       - If call matches http.* pattern but cannot resolve handler, emit UnresolvedFrameworkFact with reason UnresolvedHandler.

    4. For chi: scan call sites in files with chi import. Match callee shapes:
       - r.Get, r.Post, r.Put, r.Delete, r.Patch, r.Options, r.Head, r.Connect, r.Trace patterns (method calls on chi.Router or chi.Mux). Extract method from call name, route path from first arg, handler from second arg. Emit EntrypointFact with kind HttpRoute, framework_id "go.chi", trigger_metadata.method from call name, trigger_metadata.path from literal.
       - r.Use for middleware: emit EntrypointFact with kind HttpMiddleware.
       - r.Route for sub-router: emit with pattern prefix evidence.
       - If chi import detected but no matching registration patterns found, emit UnresolvedFrameworkFact with reason UnrecognizedPattern.

    5. For cobra: scan call sites for cobra.Command struct literals and AddCommand calls. Emit EntrypointFact with kind CliCommand, framework_id "go.cobra", trigger_metadata.tool_name from command Use field if available. Precision Conservative per D-09.

    6. For testing: scan functions in _test.go files whose names start with Test, Benchmark, Example, or Fuzz and whose file imports "testing". Emit EntrypointFact with kind Test, framework_id "go.testing", precision ResolvedStatic (naming convention is deterministic). No call site scanning needed — function name convention is sufficient.

    7. For unrecognized Go framework imports (per D-10): if a Go file imports a package that looks like a web framework (contains "router", "http", "server", "handler", "mux", "gin", "echo", "fiber", "gorilla" in the import path) but is not net/http or chi, emit UnresolvedFrameworkFact with reason UnsupportedFrameworkVersion and evidence containing the import path.

    All stable keys use semantic_stable_key(FactFamily::Entrypoint, ...) with labeled parts: language "Go", file_key, framework_id, kind, target_function_key, registration_span. provider_id is "polint.entrypoints" throughout.

    Sort output by stable key at the end.

    Add a #[cfg(test)] module with tests covering: net/http HandleFunc recognition, chi router method recognition, testing function naming, cobra command recognition, unresolved framework import detection.

    Update analysis/entrypoints/mod.rs to add pub(crate) mod recognizers_go.
