<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| generated macro metadata -> runtime capability planner | Derived capability names decide whether external rules can execute. |
| CLI manifest/facts output -> users and agents | JSON rows and diagnostics become public product contracts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T55-03 | Spoofing | Macro fact-view recognition | Mitigated | Accept only canonical SDK fact-view paths or prelude names already validated by the macro; reject aliases and lookalikes. |
| T55-04 | Repudiation | Capability diagnostics | Mitigated | Emit deterministic `polint/capability` diagnostics with docs links and manifest status rows for unsupported preview capabilities. |
| T55-05 | Tampering | Rule execution gating | Mitigated | Add a regression rule that would report a marker diagnostic if executed, then assert preview capability failure prevents that marker. |
</threat_model>
