<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arguments -> local filesystem | `init`, `new-rule`, and `check` read/write files under the current repo root. |
| `.polint.toml` -> analysis behavior | User-controlled config changes discovery, enabled rules, severities, and output. |
| source files -> diagnostic output | Repo source content is parsed and rendered into human/JSON diagnostics. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `polint init` / `new-rule` file writes | mitigate | Integration tests verify expected paths and that `init` does not overwrite an existing config. |
| T-02-02 | Tampering | `.polint.toml` glob/rule config | mitigate | Tests cover include/exclude/profile/severity behavior; invalid glob/config errors remain fatal tool errors. |
| T-02-03 | Information disclosure | JSON diagnostics | accept | Diagnostics intentionally include source file paths and messages for local/CI policy feedback. |
| T-02-04 | Denial of service | File discovery over large repos | mitigate | Continue using `ignore` and glob filtering; deeper performance/caching work remains Phase 7. |
</threat_model>
