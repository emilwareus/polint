<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fixture manifest -> filesystem | TOML manifests choose repo paths and expected relative paths; path traversal must be rejected. |
| Fixture repo -> kernel | Test-owned source files are parsed by real analysis providers and can produce diagnostics. |
| Kernel output -> eval report | Internal facts, diagnostics, metadata, and provider manifests become normalized observed items. |
| Runtime budget -> deterministic hash | Wall-clock measurement can influence pass/fail but must not make hashes machine-dependent. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-03-01 | Tampering | `load_native_fixture` | mitigate | Canonicalize fixture and repo paths, reject absolute paths, reject `..`, and require repo paths to remain under the fixture directory. |
| T-22-03-02 | Information Disclosure | `observe_kernel_fixture` | mitigate | Normalize all observed paths to fixture-relative slash paths and test that temp roots do not appear in JSON. |
| T-22-03-03 | Denial of Service | runtime budget fixture | mitigate | Support coarse `max_runtime_ms` pass/fail and avoid exact duration in hashes; fixture repos remain tiny and test-owned. |
| T-22-03-04 | Spoofing | provider-order observations | mitigate | Collect provider ids from `AnalysisKernel::provider_manifests()` rather than from fixture expected text. |
| T-22-03-05 | Elevation of Privilege | fixture content | mitigate | Do not execute fixture code; run polint analysis only on static source files copied into a temp repo. |
</threat_model>
