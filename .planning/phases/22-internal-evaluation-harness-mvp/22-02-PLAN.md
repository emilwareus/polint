<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Expected manifest data -> matcher | Fixture-provided expected items influence pass/fail outcomes and must be matched deterministically. |
| Observed analysis output -> metrics | Analyzer results become metric claims and must not overstate partial truth. |
| Runtime observations -> report | Budget information must produce pass/fail evidence without making hashes depend on exact wall-clock values. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-02-01 | Tampering | `eval::matcher` | mitigate | Match by normalized stable keys/fingerprints/endpoints only and sort match summaries deterministically. |
| T-22-02-02 | Information Disclosure | runtime budget metrics | mitigate | Store budget pass/fail counts for hashes and reports; exact observed durations do not drive deterministic hashes per Plan 22-01. |
| T-22-02-03 | Repudiation | graph/path partial truth | mitigate | Encode `Unconfirmed` outcomes for extra observed graph/path rows when ground truth is partial, preserving why rows were not counted as FP. |
| T-22-02-04 | Elevation of Privilege | matcher scope | mitigate | Matcher code must not invoke providers, extensions, shell commands, or external benchmark adapters; it compares normalized in-memory items only. |
</threat_model>
