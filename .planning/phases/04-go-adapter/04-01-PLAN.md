<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repository Go source to parser | Untrusted local source text is parsed and converted into diagnostics/facts. |
| Go adapter to core DB | Adapter-provided spans and package names enter shared `AnalysisDb`. |
| Parser diagnostics to CLI output | Parser failures become user-visible diagnostics and influence exit status. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01-01 | Denial of Service | `polint_go::analyze` | mitigate | Parser errors become diagnostics; no unwrap/panic path is allowed for malformed Go source. |
| T-04-01-02 | Tampering | `AnalysisDb::push_package` | mitigate | Assign `PackageId` internally from insertion order and cover it with unit tests. |
| T-04-01-03 | Information Disclosure | `parser/go` diagnostics | accept | Diagnostics expose only local file path/range and a stable syntax-error message, matching existing CLI behavior for local analysis. |
| T-04-01-04 | Spoofing | package extraction | accept | Package names are syntax facts, not identity/auth boundaries; semantic verification is explicitly out of scope. |
</threat_model>
