## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| syntax facts -> heuristic rule decisions | Parser-derived branch/test facts drive diagnostics that could influence developer decisions. |
| source evidence -> diagnostic output | Test names, branch text, and evidence terms are displayed in diagnostics. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04-01 | Spoofing | heuristic evidence matching | mitigate | Include `heuristic` wording in message/help/evidence and unit tests so diagnostics do not claim exact test coverage. |
| T-06-04-02 | Information Disclosure | evidence terms | mitigate | Report only branch condition/test evidence terms already extracted as facts; do not dump complete source bodies. |
| T-06-04-03 | Denial of Service | branch-to-test matching | mitigate | Match only same-file tests and same-directory companion `_test.go` files, then iterate deterministic fact slices; do not perform global fuzzy matching or regex evaluation. |
| T-06-04-04 | Repudiation | weighted score diagnostics | mitigate | Emit score components as evidence so users can reproduce why a warning fired. |
</threat_model>
