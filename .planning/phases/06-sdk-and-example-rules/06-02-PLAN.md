<threat_model>
ASVS L1 posture: no high severity threat is accepted; mitigated threats use local validation, deterministic behavior, or bounded data exposure.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.polint.toml` -> config structs | User-controlled config values enter `RuleConfig` and `RuleOptions`. |
| repository source -> parser adapters | Go and TS/JS source text is parsed into facts consumed by SDK rules. |
| literal facts -> diagnostics | Source literals can appear in diagnostic messages and evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Tampering | `RuleConfig.allow` | mitigate | Use serde defaults and exact vector copying only; invalid TOML continues to fail through existing config parsing. |
| T-06-02-02 | Information Disclosure | literal diagnostic evidence | mitigate | Rule plans that consume these facts must report only the matched literal and not dump file contents; this plan stores per-literal spans/values only. |
| T-06-02-03 | Denial of Service | Go/TS literal extraction | mitigate | Traverse parser nodes once in deterministic order and push facts without cloning full source strings. |
| T-06-02-04 | Spoofing | regex literal syntax facts | accept | Regex literals are represented as source syntax only; no trust decision is made from regex evaluation in this plan. |
</threat_model>
