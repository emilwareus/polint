<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TS/JS import string -> oxc_resolver | Untrusted repo source becomes resolver input. |
| tsconfig/package.json -> resolver setup | Repo-local config files affect resolution behavior. |
| resolver absolute path -> AnalysisDb file ID | Resolver output must be normalized back into repo-relative identities. |
| dynamic import syntax -> public facts | Dynamic expressions become visible status records, not executed code. |
| diagnostics/output -> users/agents | Resolver failures can become machine-readable diagnostics. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-03-01 | T | `module_graph::ts` path handling | mitigate | Resolve through `Resolver::resolve_file`, then map results to repo files only after lexical normalization under `loaded.root`; outside paths become external. |
| T-12-03-02 | S | package import classification | mitigate | Package-style imports and builtins become `External` nodes, never local file identities unless the normalized resolver path maps to an analyzed file. |
| T-12-03-03 | R | setup/config failures | mitigate | Map tsconfig JSON/not-found/setup failures to deterministic status/reason and diagnostics; no panics or parser diagnostics. |
| T-12-03-04 | I | raw resolver details | mitigate | Public facts expose import specifier labels, polint IDs, and status enums; do not expose `ResolveError` debug payloads or absolute paths in SDK facts. |
| T-12-03-05 | D | resolver filesystem traversal | mitigate | Construct one resolver per provider run, use fixed option lists, and rely on existing workspace include/exclude for analyzed file mapping. |
| T-12-03-06 | E | command execution for Go metadata | transfer | Not used in TS/JS resolver; Plan 12-04 owns Go command mitigation. |
</threat_model>
