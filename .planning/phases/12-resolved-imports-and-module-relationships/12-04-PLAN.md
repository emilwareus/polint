<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo root -> Go command | Repository layout determines whether `go list` is invoked. |
| Go command stdout/stderr -> metadata parser | External tool output becomes internal package metadata. |
| Go import strings -> package index | Untrusted source imports select package metadata entries. |
| metadata paths -> AnalysisDb file IDs | Absolute package files must map back under the repo root. |
| setup diagnostics -> JSON/SARIF/human output | Tool failures become machine-readable diagnostics. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-04-01 | E | `go list` execution | mitigate | Use `Command::new("go")` with fixed args `["list", "-json", "./..."]`, no shell, `current_dir(root)`, and `env_remove("GOFLAGS")`. |
| T-12-04-02 | T | Go metadata path mapping | mitigate | Normalize `Dir` + file entries lexically under repo root and map only to existing `AnalysisDb` FileIds. |
| T-12-04-03 | R | setup failures | mitigate | Convert missing `go.mod`, command errors, nonzero exit, and JSON parse errors into deterministic `SetupMissing` facts and `polint/capability` diagnostics. |
| T-12-04-04 | I | raw command output | mitigate | Do not expose raw `go list` JSON through SDK facts; diagnostic messages use bounded stable summaries and evidence fields. |
| T-12-04-05 | D | large `go list` output | mitigate | Parse streamed JSON objects with `serde_json::Deserializer` and store only package path/name/file mappings needed for resolution. |
| T-12-04-06 | S | stdlib/dependency classification | mitigate | Standard/dependency packages become `External` nodes so they are not confused with missing local files. |
</threat_model>
