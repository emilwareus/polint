<objective>
Add the closed `IdentityCategory` taxonomy and a pure projection module `analysis::identity::categorize` that maps every existing v1.2 unresolved/unsupported source variant to exactly one of the five categories. Extend `eval::report::MetricSections` with a `categorized_failures` counter map (five `u32` fields, snake_case discriminators) and wire the eval runner to populate it without changing the existing `MetricSummary` shape. Land a fixture that exercises four of five categories from real source PLUS a `#[cfg(test)]` unit test that drives `record_category(ModelMissing)` directly so all five `categorized_failures.*` counters are proven non-zero in some test (no silent scope reduction of D-15).

Purpose: IDENT-03 requires evaluation output to distinguish identity-vs-unsupported categories so downstream metrics become trustworthy. Without explicit categorization, every Phase 43+ scoring decision conflates "polint named the right place wrong" with "polint couldn't resolve the callee" with "Go packages failed to load" — they need different remediation paths. The closed-enum design (no `Other`) forces every classification to be deliberate, and the per-fact `Reason` tag keeps it composable without inventing new fact families.

Output: One new file `analysis::identity::categorize.rs`, modifications to `eval::report.rs`, `eval::runner.rs`, and `eval::metrics.rs`, one fixture pair under `tests/eval-fixtures/identity/categorized_failures/`.

Wave 3 dependency rationale (BLOCKER #3 fix): Plan 02 lands `JellyOracleCoverageSection` in `eval/report.rs` and the renderer module under `analysis/identity/render/`. Plan 03 adds `CategorizedFailureSection` as a SIBLING field placed AFTER `jelly_oracle_coverage` in `MetricSections` (so iteration order is `... adaptation, jelly_oracle_coverage, categorized_failures`). Plan 03 also adds the `categorize` submodule to `analysis/identity/mod.rs` AFTER the `render` submodule line that Plan 02 introduces. This makes Plan 03 strictly Wave 3 — running it in Wave 2 alongside Plan 02 would race on `eval/report.rs` and `analysis/identity/mod.rs`.
</objective>
