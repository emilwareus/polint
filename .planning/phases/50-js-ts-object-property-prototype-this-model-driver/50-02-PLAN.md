<threat_model>
## Trust Boundaries

| Boundary | Risk | Mitigation |
|----------|------|------------|
| Repo config enables expensive analysis | A repo can enable object modeling and cause solver blowup. | Object model is opt-in and bounded by finite caps folded into cache digests. |
| Cache reuse across flag changes | Disabled and enabled runs could share solver output. | Flag state and all object caps participate in parameter and output digests. |
| Config typo with zero cap | `0` could silently disable proof or truncate all output. | Positive-only overlay treats zero as default, matching Go/TS token behavior. |

## STRIDE Notes

- Tampering: object-model flag/caps are part of deterministic cache identity.
- Denial of service: every object dimension has a finite cap before the solver policy lands.
- Information disclosure: the flag is config-only; no SDK or CLI graph surface is promoted.
</threat_model>
