<threat_model>
## Trust Boundaries

| Boundary | Risk | Mitigation |
|----------|------|------------|
| Prototype chains | Cycles or deep inheritance can create unbounded traversal. | Visited-set termination and `max_prototype_depth` cap with budget evidence. |
| Receiver binding | Incorrect `this` binding can create high-confidence false positives. | Model only stable roadmap-named receiver forms; leave unknown native/framework cases unresolved. |
| Accessor/prototype mutation | Reflective mutation can hide arbitrary behavior. | Support only direct stable facts; dynamic mutation remains unsupported evidence. |

## STRIDE Notes

- Tampering: deleting receiver/prototype facts changes derived edge provenance.
- Denial of service: prototype depth, receiver candidates, and worklist caps bound traversal.
- Spoofing: receiver identity must be an object token, not a TypeScript declared type.
</threat_model>
