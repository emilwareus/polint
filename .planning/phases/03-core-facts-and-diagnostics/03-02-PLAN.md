<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rule diagnostics to renderer | Rule-provided messages, evidence, suggestions, and fixes become terminal/JSON output. |
| Diagnostics to CI consumers | JSON output may be consumed by automation that expects stable fields and parseability. |
| Diagnostic identity to dedupe | Fingerprints decide whether diagnostics collapse as duplicates. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Tampering | `stable_fingerprint` | mitigate | Compute fingerprints from rule/file/full-range/message and test that field changes affect identity. |
| T-03-02-02 | Denial of Service | `render(OutputFormat::Json)` | mitigate | Keep JSON rendering through `serde_json` and test parseability; fallback remains bounded to `[]`. |
| T-03-02-03 | Repudiation | Human/JSON renderers | mitigate | Include stable fingerprint in human output and JSON so diagnostics can be correlated across runs. |
| T-03-02-04 | Information Disclosure | Diagnostic messages/fixes | accept | Diagnostics intentionally display local repository paths and rule-provided text to local users; this plan adds no external transmission. |
</threat_model>
