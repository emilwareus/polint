<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rule implementation to runner | Repo-local rule code is trusted enough to execute in-process but may panic or return errors. |
| Parser facts to core DB | Language adapters supply offsets, strings, and facts that must not corrupt ordering or diagnostics. |
| Core DB to diagnostics | Core spans become user-visible locations through a narrow conversion method. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01-01 | Tampering | `AnalysisDb` push methods | mitigate | Keep IDs assigned internally from Vec length and test deterministic insertion order; callers cannot choose final function/import/branch IDs. |
| T-03-01-02 | Denial of Service | `run_rules` | mitigate | Wrap rule execution with `catch_unwind` and convert panics/errors into diagnostics so one rule cannot crash the process. |
| T-03-01-03 | Spoofing | Enabled rule matching | mitigate | Keep exact and `prefix/*` matching tests so enabled filters cannot accidentally run unrelated rule IDs. |
| T-03-01-04 | Information Disclosure | Internal diagnostics | accept | Internal diagnostics include only rule ID, file path, and error text already visible to local CLI users; no secrets are introduced in this plan. |
</threat_model>
