<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Provider execution -> run report | Provider diagnostics and cache stats cross into internal provider-output metadata. |
| Provider manifests -> cache identity | Manifest ids, schema versions, cache policies, and precision ceilings become active inputs to report construction. |
| Run report -> tests/eval | Internal report helpers must remain test-facing and absent from public JSON/SDK/runner surfaces. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-04-01 | Repudiation | provider output metadata | mitigate | Build one metadata row per manifest id in manifest order and test exact ids/schema labels. |
| T-23-04-02 | Spoofing | manifest consumption | mitigate | Remove synthetic manifest weight token and consume manifest ids/schema/cache policies in snapshot/report construction. |
| T-23-04-03 | Information Disclosure | report test helpers | mitigate | Keep helpers under `#[cfg(test)]` and grep public modules for `run_report`, `InputSnapshot`, `ProviderOutputMeta`, and `CacheStats`. |
| T-23-04-04 | Tampering | cache stats claims | mitigate | Use real Go/TS stats from adapter wrappers and zero-valued stats for providers with no cache access; do not increment verified reuse or quarantine counters. |
</threat_model>
