<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Existing string cache keys -> typed internal keys | Existing `CacheKey`, config hash, rule hash, and plan hash data become typed internals without changing current cache file identity. |
| Internal cache vocabulary -> public API | New identity types must remain crate-private and absent from SDK, runner, crate-root exports, CLI, docs, and public JSON. |
| Variable input lists -> deterministic keys | Lists of source, lifecycle, dependency, model, and extension digests must not depend on traversal order. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01-01 | Tampering | `Digest::from_parts` | mitigate | Length-prefix every labeled part before hashing and unit-test kind separation and repeated determinism. |
| T-23-01-02 | Repudiation | `LayerKey`/`QueryKey` equality | mitigate | Sort every variable digest list canonically and test equality for reversed inputs. |
| T-23-01-03 | Information Disclosure | public API boundary | mitigate | Keep module under `analysis_kernel`, use only `pub(crate)`, and grep `lib.rs`, `sdk`, `runner`, and `cli` for absent exports. |
| T-23-01-04 | Denial of Service | accidental stale reuse from untyped compatibility bridge | mitigate | Preserve existing `CacheKey` inputs as typed digest components instead of deleting or weakening current cache identity. |
</threat_model>
