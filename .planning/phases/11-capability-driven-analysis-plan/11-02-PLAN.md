<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| child local-rule host to analysis pipeline | Registered local rules decide the real plan; unsupported capability diagnostics must be controlled output. |
| analysis plan to adapter cache | Plan digest crosses into cache identity; stale cache hits are correctness failures. |
| parallel adapter execution | Per-file work is parallel but fact insertion and diagnostics must remain deterministic. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-02-01 | Tampering | `CacheKey::stable_id` | mitigate | Include `plan_hash` in `stable_id()` and test `cache_key_changes_with_plan_hash`. |
| T-11-02-02 | Denial of Service | `runner::analyze_and_run` | mitigate | Build the plan before file loading and avoid parsing source in plan construction; unsupported capabilities become diagnostics, not adapter crashes. |
| T-11-02-03 | Repudiation | adapter outputs | mitigate | Keep existing deterministic result sorting by `file_id` in Go and TS/JS adapters after adding plan input. |
| T-11-02-04 | Elevation of Privilege | local rule execution | accept | Repo-local rules are intentionally executed local code; this plan does not add shell delegation and preserves existing cargo invocation boundaries. |
| T-11-02-05 | Denial of Service | plan-time rule metadata/capability collection | mitigate | Wrap plan-time `meta()` and `capabilities()` calls in panic containment and convert failures to deterministic `polint/capability` diagnostics or controlled internal errors. |
</threat_model>
