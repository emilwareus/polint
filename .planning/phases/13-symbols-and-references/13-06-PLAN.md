## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external temp repo -> local rule host | Test repositories compile repo-local rule crates against the public SDK. |
| provider facts -> machine-readable diagnostics | Rule diagnostics expose IDs, names, precision, and status in JSON. |
| docs/skill text -> user behavior | Public guidance shapes how rule authors consume capabilities. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-06-01 | Spoofing | external rule proof | mitigate | Tests reject internal imports and require facts from public `Symbols<'_>`/`References<'_>` views through `polint::sdk::prelude::*`. |
| T-13-06-02 | Tampering | supported capability promotion | mitigate | Planner tests prove support rows are Supported only after provider plans and setup-missing overrides still block affected rules. |
| T-13-06-03 | Repudiation | JSON diagnostics | mitigate | External tests parse `PolintReport` and assert evidence labels for ID, precision, status, and target instead of substring checks. |
| T-13-06-04 | Information Disclosure | docs and diagnostics | mitigate | Docs and tests expose IDs/names/spans only; no source bodies, raw Oxc IDs, Go object addresses, or sidecar JSON structures appear in public guidance. |
| T-13-06-05 | Denial of Service | external CLI tests | mitigate | Tests use focused temp repos and targeted cargo test filters; full workspace verification remains the final gate. |
</threat_model>
