<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| analysis plan -> provider scheduling | Repo-local rule signatures decide which derived stages execute. |
| module graph facts -> symbol graph provider | Relationship facts influence cross-file symbol/reference linking. |
| provider diagnostics -> CLI JSON | Setup/support failures become user-visible diagnostics. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-03-01 | Tampering | provider sequencing | mitigate | Task 3 tests exact runner order and support-view merge so rules cannot run before provider diagnostics/support rows are applied. |
| T-13-03-02 | Repudiation | setup/support diagnostics | mitigate | `SymbolGraphDerivation` emits deterministic `polint/capability` diagnostics with capability, status, reason, and docs path evidence. |
| T-13-03-03 | Information Disclosure | language contracts | mitigate | `ts.rs` and `go.rs` contracts are crate-private and expose only normalized drafts/facts, never parser IDs, raw AST nodes, or sidecar JSON. |
| T-13-03-04 | Denial of Service | derived stage execution | mitigate | The provider returns default output unless `symbols` or `references` are requested; module graph work expands only for those capability names. |
</threat_model>
