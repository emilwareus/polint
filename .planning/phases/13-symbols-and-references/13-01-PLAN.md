<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo-local rule source -> macro expansion | Rule authors control function signatures that produce capability requests. |
| internal fact storage -> public SDK | Facts cross from trusted engine internals into stable rule-author API. |
| source-derived stable keys -> diagnostics/cache evidence | Names and paths from analyzed repositories become observable fact fields. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01-01 | Spoofing | `SymbolId`/`DefinitionId`/`ReferenceId` | mitigate | Provider-computed IDs must be deterministic hash IDs from normalized stable keys; Task 1 rejects vector-position ID assignment with tests and grep. |
| T-13-01-02 | Tampering | `Capabilities::references()` and macro mapping | mitigate | Task 3 tests canonical SDK view mapping and ensures `References<'_>` always enables `symbols` internally. |
| T-13-01-03 | Information Disclosure | `SymbolFact::stable_key` | mitigate | Task 1 stores debug-safe normalized key material only: language, path/package/module identity, owner chain, names, kinds, and spans; no full source text or raw AST dumps. |
| T-13-01-04 | Denial of Service | SDK query methods | mitigate | Task 1 builds private BTree indexes and Task 2 uses them for symbol/reference lookups instead of repeated broad scans for hot queries. |
</threat_model>
