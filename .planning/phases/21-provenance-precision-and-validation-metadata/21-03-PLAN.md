<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Provider outputs -> KernelOutput | Facts must pass metadata validation before rule execution receives KernelOutput. |
| Stable key index -> Fact vectors | Duplicate/conflicting stable keys must not silently alter identity. |
| Source spans -> diagnostics/evidence | Invalid spans could mislead diagnostics or downstream evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-03-01 | Tampering | stable-key merge | mitigate | `FactMetaStore` stores first owner, idempotently collapses identical payloads, and records conflicting payloads as deterministic diagnostics. |
| T-21-03-02 | Repudiation | validation diagnostics | mitigate | Diagnostics include family, stable key or ref, producer id, and deterministic evidence fields. |
| T-21-03-03 | Information Disclosure | validation output | mitigate | Diagnostics expose stable keys and relative/source-level metadata only; no absolute machine paths, timestamps, or memory addresses are included. |
| T-21-03-04 | Elevation of Privilege | precision ceilings | mitigate | Provider metadata is checked against manifest precision ceilings so a syntax provider cannot label unsupported or heuristic output as higher precision without a diagnostic. |
| T-21-03-05 | Denial of Service | validation traversal | accept | Validation walks existing vectors once with BTree indexes; it does not parse source again or clone full source text. |
</threat_model>
