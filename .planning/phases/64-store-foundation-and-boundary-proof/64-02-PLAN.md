<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem SQLite bytes → rusqlite | Local cache content may be corrupt, malicious, truncated, or from a newer binary |
| concurrent polint process → writer lease | Separate invocations contend for the same local store |
| typed store facade → kernel | The kernel receives status only; no raw connection/error/SQL crosses the boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-64-02-01 | Tampering / Elevation | symlinked store path targets files outside cache | mitigate | Validate every existing ancestor and managed target before SQLite open/remove; explicit rebuild requires canonical containment and refuses symlinks. |
| T-64-02-02 | Tampering | future schema destroyed by fallback | mitigate | Future schema is a dedicated non-destructive status; maintain and rebuild tests assert version/sentinel preservation. |
| T-64-02-03 | Denial of Service | indefinite SQLITE_BUSY wait | mitigate | 250ms bounded busy timeout; second writer maps busy/locked to `BusySkipped`; test asserts sub-second completion. |
| T-64-02-04 | Tampering / Repudiation | concurrent writers interleave partial bootstrap state | mitigate | `BEGIN IMMEDIATE` single-writer lease plus transactional migrations; contention fixture ends with `integrity_check == ok`. |
| T-64-02-05 | Denial of Service | malformed database panics policy analysis | mitigate | Map rusqlite open/query failures into typed rebuild-needed/skipped outcomes; no production unwrap/expect; corruption test proves no panic/deletion. |
| T-64-02-06 | Information disclosure | raw database errors reveal SQL/table internals | mitigate | `StoreStatus` uses stable private reason categories; raw error strings/SQL never enter public diagnostics or crossing types. |
</threat_model>
