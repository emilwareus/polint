<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internal manifest metadata -> tests | Provider manifests describe internal execution metadata that could become misleading if nondeterministic or accidentally public. |
| crate-private kernel -> public SDK/CLI | Any manifest export crossing into SDK, runner public APIs, or stable CLI output would widen the product contract. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-04 | I | provider order report | mitigate | Test-facing report contains only ids/kinds/scopes/inputs/outputs and excludes timestamps, absolute paths, and machine-local data. |
| T-20-05 | E | manifest visibility | mitigate | Keep manifest module private under a crate-private parent and add `rg` acceptance checks against SDK, runner public API, and CLI exposure. |
| T-20-06 | T | manifest dependency data | mitigate | Unit tests assert deterministic static dependency metadata, and `AnalysisKernel::run` remains the source of execution behavior for this phase. |
</threat_model>
