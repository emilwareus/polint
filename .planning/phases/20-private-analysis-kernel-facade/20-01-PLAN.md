<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo source/config -> kernel | Repository files and `.polint.toml` are untrusted inputs loaded into `AnalysisDb` and provider options. |
| kernel -> rule execution | Kernel-produced facts and capability support control whether repo-local rules run and what typed views they see. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01 | T | `analysis_kernel::AnalysisKernel::run` | mitigate | Preserve existing parser/provider diagnostics and return `anyhow::Result<KernelOutput>`; do not panic on file-loading failures. |
| T-20-02 | E | `crates/polint/src/lib.rs` | mitigate | Register the kernel as `pub(crate) mod analysis_kernel;` only, with no SDK, crate-root public, or CLI exposure. |
| T-20-03 | D | provider execution | accept | This phase keeps the existing eager provider sequence and current parallel parser behavior; demand scheduling is out of phase scope. |
</threat_model>
