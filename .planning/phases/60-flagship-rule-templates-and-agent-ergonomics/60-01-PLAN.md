# Phase 60-01 Plan: Template Selector and Rule Bodies

## Goal

Extend `polint new-rule` with one clear flagship-template selector while keeping
the default language skeleton unchanged.

## Tasks

1. Add a closed `RuleTemplateKind` value enum exposed as
   `polint new-rule <lang> <name> --template <id>`.
2. Preserve existing default generation when `--template` is absent.
3. Generate policy-query rule bodies for:
   - `request-to-shell`
   - `secret-to-log`
   - `pii-to-analytics`
   - `sensitive-write-guard`
   - `transaction-cleanup`
   - `raw-reachable-api`
   - `ssrf`
   - `dangerous-html`
   - `unsafe-deserialization`
   - `user-file-path`
4. Keep every generated rule on the same pattern:
   - `use polint::sdk::prelude::*;`
   - one typed preview policy view parameter
   - one query object with explicit option fields
   - `ctx.report(violation.diagnostic(ctx.rule_id(), "..."))`
5. Add unit/integration assertions that generated modules contain public SDK
   imports only and do not mention internal modules, manual `Rule`
   implementations, or `Capabilities::new`.

## Verification

- `cargo test -p polint --test cli new_rule_ --locked`
- `cargo fmt --all --check`
