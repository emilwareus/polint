<objective>
Implement interprocedural summary closure over SCCs with fixpoint iteration, widening, and backdating.

Purpose: Per D-03, Phase 33 has one concrete demand-driven consumer: summary SCC closure. Direct summaries from Phase 32 are local per-function. This plan applies callee summaries to improve caller summaries, processing SCCs in reverse topological order. Per D-05, non-recursive SCCs are single-pass; recursive SCCs iterate with widening bounded by a configurable budget. Per D-06, backdating compares new summary digests against cached digests — if equal, the invalidation cascade stops. Per D-07, SCC-level results are stored as a unit.

Output: New closure.rs module with SCC closure logic. Provider and kernel wired to run closure after direct summary computation. Demand query engine records SCC closure queries.
</objective>

  <action>
    Create closure.rs as a new crate-private module under analysis/summaries/.

    Define SccClosureConfig (Clone, Debug) with fields: max_iterations (u32, default 100), and enable_backdating (bool, default true).

    Define SccClosureResult (Clone, Debug, Serialize) with fields: total_sccs_processed (usize), non_recursive_sccs (usize), recursive_sccs (usize), budget_exceeded_sccs (usize), backdated_sccs (usize — SCCs whose summary digests did not change), total_iterations (usize — sum across all recursive SCCs), updated_summaries (usize), and scc_iteration_counts (Vec of (Vec of String, u32) — member stable keys and iteration count for recursive SCCs).

    Implement close_summaries_by_scc as a pub(crate) function taking: db (&mut AnalysisDb), schedule (&SccSchedule), config (&SccClosureConfig), demand_engine (&mut DemandQueryEngine), and previous_scc_digests (BTreeMap of Vec of String to Digest — keyed by sorted member stable keys from previous run for backdating). Returns SccClosureResult.

    Processing logic for each SCC in schedule.sccs (already in reverse topological order):
    1. For non-recursive SCCs (single function, no self-call per D-05): Read the function's existing direct summaries from AnalysisDb. For each callee that this function calls (from CallStore outgoing targets), look up the callee's current summaries. Apply callee summary effects to improve the caller's summary — specifically: join callee control effects into the caller's call-effect summary, propagate callee memory effects through TITO edges where the caller passes arguments, and mark unknown-callee calls where callee summaries are missing or BudgetExceeded. Store the updated summary. Compute a digest of the SCC's output summaries.
    2. For recursive SCCs (per D-05): Initialize each member's interprocedural summary state from its direct summary. Iterate: for each member in deterministic order (sorted by stable_key per D-17), recompute its summary using current callee summaries from other SCC members plus external callees. Apply widening after each iteration using the domain's widen method. Check convergence via less_equal. If all members converge, break. If max_iterations is reached, mark all members as BudgetExceeded per D-05 and record the event with SummaryTopReason::BudgetExceeded.
    3. After computing each SCC, compute a digest of the SCC's output summaries (all members' summary payload digests combined). Compare against previous_scc_digests for backdating per D-06: if the digest matches the previous run's digest for this SCC, record a backdating event (summary didn't actually change).
    4. Record each SCC computation as a demand query entry in the demand_engine for trace purposes.

    The callee summary application should be conservative: for each callee call in the function, if the callee has a resolved direct target with summaries available, use those summaries. If the callee is unresolved or has no summary, treat it as unknown_top(UnresolvedCallee). This follows the Phase 32 D-06 "missing callees produce unknown/havoc summaries."

    For the initial implementation, callee summary application should focus on: (a) joining callee ControlEffects into the caller's CallEffects (callee may throw/panic propagates to caller), (b) joining callee MemoryEffects for pass-through arguments (if caller passes its param[i] to callee param[j] and callee writes param[j], then caller has transitive memory effect on param[i]), (c) marking unresolved-callee entries with unknown top reasons.

    In mod.rs, add pub(crate) mod closure;.

    Add unit tests:
    (a) Non-recursive SCC with a callee that throws — caller's call-effects summary should record the throw propagation.
    (b) Recursive SCC with two mutually-calling functions — should converge within max_iterations or produce BudgetExceeded.
    (c) Backdating test: process same SCC twice with same inputs, verify backdated_sccs == 1 on second run.
