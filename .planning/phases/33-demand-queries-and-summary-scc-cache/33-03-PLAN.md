<objective>
Build the summary call graph from direct call target facts and compute SCCs using Tarjan's algorithm, scheduled in reverse topological order.

Purpose: Per D-04, SCC discovery uses Phase 30 direct call targets. For each function with a direct summary, it discovers callees and computes strongly connected components. Per D-17, scheduling must be deterministic — independent SCCs are ordered by sorted stable keys of their member functions. Per D-05, non-recursive SCCs are marked for single-pass computation; recursive SCCs are marked for iterative fixpoint.

Output: New scc.rs module with SccSchedule, Scc types, and compute_scc_schedule function. SCC debug info records number of SCCs, sizes, and processing order per D-14.
</objective>

    Create scc.rs as a new crate-private module under analysis/summaries/.

    Define Scc (Clone, Debug, PartialEq, Eq, Serialize) with fields: members (Vec of FunctionId — sorted for determinism per D-17), member_stable_keys (Vec of String — sorted, for debug/stable identity), is_recursive (bool), and size (usize).

    Define SccSchedule (Clone, Debug, Serialize) with fields: sccs (Vec of Scc — in reverse topological order per D-04: leaf callees first), total_functions (usize), total_sccs (usize), recursive_scc_count (usize), and max_scc_size (usize).

    Define SccScheduleDebug (Clone, Debug, Serialize) with fields: total_sccs, total_functions, recursive_scc_count, max_scc_size, scc_sizes (Vec of usize), and processing_order (Vec of Vec of String — stable keys per SCC).

    Implement compute_scc_schedule as a pub(crate) function taking AnalysisDb reference. Steps:
    1. Collect the set of FunctionId values that have at least one SummaryFact in the SummaryStore (these are the functions with direct summaries computed in Phase 32).
    2. Build a DiGraph<FunctionId, ()> using petgraph. For each function in the set, add a graph node. For each function, query CallStore::outgoing_by_function to get outgoing call targets. For each target with status Resolved and a target_function that is also in the summary set, add a directed edge from caller to callee. Self-calls create self-edges.
    3. Use petgraph::algo::tarjan_scc to compute SCCs. Tarjan's returns SCCs in reverse topological order already.
    4. For each SCC: sort members by the function's stable_key from AnalysisDb for determinism per D-17. Determine is_recursive: true if SCC has more than one member, or if a single member has a self-edge.
    5. Build SccSchedule from the SCCs.

    Implement SccSchedule::debug_info(&self) -> SccScheduleDebug that extracts summary statistics.

    In mod.rs, add pub(crate) mod scc;.

    Add unit tests in scc.rs:
    (a) Empty AnalysisDb produces SccSchedule with 0 SCCs.
    (b) Test with a mock scenario description proving deterministic ordering: given functions A->B->C (chain), SCCs should be [C], [B], [A] in that order.
    (c) Test that a self-calling function produces a recursive SCC of size 1.
    (d) Test that independent functions (no call edges between them) are scheduled in sorted stable-key order.
