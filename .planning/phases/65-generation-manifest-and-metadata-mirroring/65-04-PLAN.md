<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Validator detection/context → `ValidationIssue` | Family/provider ownership can narrow a global fail-closed downgrade and therefore must be structured and authenticated. |
| `ValidationIssue` → rendered `Diagnostic` | Rendering is an observation channel; text/evidence/fingerprint changes must never feed back into provider trust. |
| Untrusted layer-cache bytes → provider success | Decode/validation and recomputation must precede any success identity. |
| Sealed `KernelOutput` → production rule dispatch/exit | Warm state must not change capability support, blocker consumption, policy answers/order, or exit behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-65-04-01 | Tampering | `validation.rs` ownership collection | mitigate | Accept family only from explicit `FactFamily`/`FactRef`; accept provider/layer IDs only after manifest authentication; sort/deduplicate; otherwise keep the issue global. |
| T-65-04-02 | Spoofing | Diagnostic message/evidence → trust downgrade | mitigate | Keep Diagnostic rendering one-way and test that changing reason/evidence cannot change family/provider ownership or downgrade results. |
| T-65-04-03 | Tampering | Layer-cache payload → `Succeeded` | mitigate | Preserve real corrupt-blob typed rejection plus eviction/recompute (or honest failure) before success identity. |
| T-65-04-04 | Repudiation | Partial cold/warm equality claim | mitigate | Compare one typed semantic projection containing capabilities, outcomes/identities/blockers, production dispatch counters/decisions, sorted policy diagnostics/answers/order, and production exit byte; assert telemetry actually differs. |
| T-65-04-05 | Denial of Service | Verification/runtime expansion | mitigate | Keep isolated focused tests below sixty seconds with no sleeps, environment mutation, global serialization, network, Go toolchain build, or full-repo fixture. |
| T-65-04-06 | Elevation of Privilege | Private gap fix widens supported surface | mitigate | Keep helpers crate-private/test-only and run public leak/store parity gates; forbid SDK/CLI/schema/store/CI changes. |
</threat_model>
