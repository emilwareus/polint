## Trust Boundaries

| Boundary | Description | Data Crossing |
|---|---|---|
| Concurrent workspaces to first writer | Competing processes attempt initial ownership/reservation | Workspace identities, pending generation rows |
| Pending generation to active publication | Validated metadata becomes reader-visible truth | All generation rows, complete status, active pointer |
| Rolled-back publication to audit transaction | A trusted failed attempt receives sanitized bookkeeping | Generation handle, reason/stage codes |

## Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-65-17-01 | Spoofing | Workspace binding | mitigate | Bind+reserve in one immediate transaction and force both race orderings. |
| T-65-17-02 | Tampering | Generation publication | mitigate | Write/validate/complete/activate in one transaction with final-point rollback injection. |
| T-65-17-03 | Repudiation | Failure audit | mitigate | Revalidate exact trusted attempt and persist only closed reason/stage codes. |
| T-65-17-04 | Information Disclosure | Failure bookkeeping | mitigate | Store no raw error, SQL, path, environment value, free text, or blob. |
| T-65-17-05 | Denial of Service | Active reader | mitigate | Explicit active+complete selection ignores newer failed/pending attempts and telemetry. |
</threat_model>
