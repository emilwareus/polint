<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pinned public repo content → polint parser | Untrusted third-party source (grafana/hugo/excalidraw) parsed by polint during measurement |
| manifest checkout.path → filesystem | Manifest-declared clone path resolved on the local/CI filesystem |
| local-only devloupe repo → harness | Private absolute-path checkout allowed only via explicit AllowAbsolute policy |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-63-01-01 | Tampering | manifest checkout.path traversal | mitigate | Public manifests use `local_clone_policy = repo_relative_only`; `validate_suite_path` (existing) rejects absolute/`..` paths at parse time; validation test enforced in Task 1. |
| T-63-01-02 | Elevation | absolute-path checkout (devloupe) | mitigate | AllowAbsolute is opt-in per-manifest, devloupe is declared local-only with only a `research` tier so CI never resolves it; documented in BENCHMARK-SUITE.md. |
| T-63-01-03 | Denial of Service | resource exhaustion parsing large untrusted repos | accept | Measurement is the intended workload; existing kernel budgets (BudgetExceeded) bound per-file cost. Budget-exhaustion counters are recorded, not silently swallowed. |
| T-63-01-SC | Tampering | cargo dependency (`libc`) | mitigate | `libc` is already resolved and vetted in Cargo.lock (cargo-deny/RustSec gates apply); promoting it to a direct dependency adds no new registry package. No new `[ASSUMED]`/`[SUS]` package is introduced. |
</threat_model>
