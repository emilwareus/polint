<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Disk cache -> adapter facts | Cache files are untrusted JSON and may be missing, disabled, valid, or corrupt. |
| Adapter stats -> kernel metadata | Cache counters describe current behavior only and must not claim verified reuse or layer invalidation. |
| Compatibility wrappers -> existing callers | Existing adapter functions used by tests and bench-facing wrappers must keep their diagnostic-only contract. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-03-01 | Tampering | corrupt cache JSON | mitigate | `read_json_with_status` evicts invalid JSON and reports `InvalidEvicted` while returning `None`. |
| T-23-03-02 | Repudiation | cache stats | mitigate | Count disabled, miss, hit, invalid, recompute, and write outcomes explicitly in adapter tests. |
| T-23-03-03 | Denial of Service | public adapter compatibility | mitigate | Preserve existing `analyze_with_plan_options` wrappers returning `Vec<Diagnostic>` and route stats through new crate-private wrappers only. |
| T-23-03-04 | Spoofing | verified reuse/quarantine counters | mitigate | Keep `verified_reuse` and `quarantines` zero in current-cache instrumentation; do not implement Phase 24/34 semantics. |
</threat_model>
