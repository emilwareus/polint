<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MIR facts -> CFG facts | CFG rows consume internal MIR identity and must not invent public or parser-owned identity. |
| CFG internals -> public SDK/CLI | New CFG facts must stay crate-private and unsupported publicly unless deliberately promoted later. |
| CFG storage -> downstream providers | Invalid or duplicate rows must remain visible for validation instead of being silently deduplicated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-01-01 | I | CFG visibility | mitigate | Add only crate-private modules/types and assert no SDK, runner, public CLI, or docs promotion. |
| T-29-01-02 | T | Stable CFG identity | mitigate | Keep run-local dense IDs separate from stable keys and test deterministic normalization. |
| T-29-01-03 | R | Metadata/provenance | mitigate | Attach `polint.cfg` metadata to every CFG fact family through `AnalysisDb::replace_cfg_facts`. |
| T-29-01-04 | T | Duplicate/conflicting rows | mitigate | Preserve duplicate rows in normalized output so validation can produce deterministic diagnostics. |
</threat_model>
