<objective>
Add the demand query infrastructure contracts: DemandQueryEngine with in-run memoization, query result types, and query trace recording.

Purpose: Per D-02, the demand layer supports two modes: in-run memoization (computed once, reused within same kernel run) and cross-run caching (QueryKey-addressed results persist to layer cache). This plan delivers the memoization and trace infrastructure. Cross-run persistence is exercised by Plan 04 (SCC closure) which is the first concrete demand-driven consumer per D-03. Per D-13, query trace output records query kind, precision tier, input digests, cache hit/miss, compute time, and result digest.

Output: New demand.rs module with DemandQueryEngine, DemandQueryResult, DemandQueryTrace, and trace entry types. KernelRunReport extended to include demand_query_trace field.
</objective>

    Define DemandQueryTraceEntry (Clone, Debug, Serialize) with fields: query_kind (String), query_version (String), parameter_digest (String — display form), input_layer_digests (Vec of String), cache_status (String — "hit", "miss", "recomputed"), compute_duration_micros (u64), result_digest (String), precision_tier (String).

    - insert(&mut self, result: DemandQueryResult) — stores result in memo and records trace entry with cache_status="computed"

    - into_trace(self) -> DemandQueryTrace — consumes engine, returns trace
    - trace(&self) -> &DemandQueryTrace — borrows trace

    In mod.rs, add pub(crate) mod demand; and re-export DemandQueryEngine, DemandQueryResult, DemandQueryTrace, and DemandQueryTraceEntry.

    Add unit tests in demand.rs: (a) insert then lookup returns the result, (b) lookup for absent key returns None, (c) trace records entries in insertion order, (d) into_trace is not empty after inserts.
