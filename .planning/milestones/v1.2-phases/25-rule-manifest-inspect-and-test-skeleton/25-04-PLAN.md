<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `new-rule` generator -> user repository | Generated files become user-owned source and fixture artifacts. |
| Documentation -> public product contract | Docs and schemas describe what users and agents can rely on. |
| Generated rule code -> public SDK boundary | Generated code must not depend on private internals. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-04-01 | Tampering | `new-rule` scaffold | mitigate | Do not overwrite existing rule or fixture files; tests assert existing-file behavior. |
| T-25-04-02 | Spoofing | generated rule API | mitigate | Integration test rejects internal imports, manual capabilities, parser adapters, and manual `impl Rule`. |
| T-25-04-03 | Information Disclosure | generated test JSON | mitigate | Final no-leak tests assert inspect/test/check JSON omit temp roots, cache paths, kernel/cache/provider internals, and source text. |
| T-25-04-04 | Repudiation | docs/schema mismatch | mitigate | Tests parse schemas and docs list exact supported commands/fields. |
| T-25-04-05 | Denial of Service | generated fixture default | mitigate | Generated fixture must either pass as an empty skeleton or use an explicitly supported todo mechanism; it must not create a permanently failing default `polint test`. |
</threat_model>
