# Quick Task 260521-a5k: Fix CFG PR Review Findings

## Goal

Address the three review findings in PR #34:

1. Derived CFG fact stable keys must not depend on run-local dense IDs.
2. Go and TS/JS CFG lowering must connect ordinary fallthrough to the normal exit.
3. CFG validation must enforce entry/exit and reachability-shape invariants.

## Tasks

### 1. Stable Derived Keys

Files:
- `crates/polint/src/analysis/cfg/derived.rs`

Action:
- Build derived reachability, dominator, postdominator, and control-dependence stable keys from existing CFG function/block/edge stable keys, not dense IDs.
- Add a regression test proving derived stable keys are unchanged when equivalent graphs use different dense IDs.

Verify:
- `cargo test -p polint --lib analysis::cfg::derived --locked`

### 2. Implicit Normal Exit Edges

Files:
- `crates/polint/src/analysis/cfg/lower_go.rs`
- `crates/polint/src/analysis/cfg/lower_ts.rs`

Action:
- Add a normal edge from the current fallthrough block to the normal exit when lowering reaches the end of a non-terminated body.
- Add Go and TS/JS tests for implicit-return fallthrough.

Verify:
- `cargo test -p polint --lib analysis::cfg::lower_go analysis::cfg::lower_ts --locked`

### 3. CFG Validation Invariants

Files:
- `crates/polint/src/analysis/cfg/validate.rs`
- `crates/polint/src/analysis_kernel/validation.rs`

Action:
- Validate exactly one entry block per CFG function, at least one selected exit block, and stored block reachability matching graph reachability.
- Add focused validation coverage for these invariants.

Verify:
- `cargo test -p polint --lib analysis_kernel::validation::cfg --locked`
