# W1.5 step 1 — parse cost measurement (mandatory checkpoint)

**Branch:** `swarm/W1.5` @ tip of `static-analysis-architecture-review` (`7abad5a4` + instrumentation)  
**Date:** 2026-08-08  
**Verdict:** **ESCALATE / not-worth-doing** — parse wall-clock is a small fraction of the run.

## Method

- Env-gated counters in `crates/polint/src/ts/parse_metrics.rs`, wrapping every production Oxc `Parser::new(...).parse()` site.
- Enabled via `POLINT_MEASURE_TS_PARSE=1` in `polint::runner::run_cli` (rules-host path used by golden examples).
- Corpus: M0.A TS-bearing golden example self-pairs (`examples/*` × own rules × `check --format json --no-cache`).
- Wall clock = rules-host process time after enable (excludes outer `cargo` rules-host compile).

## Results

|---|---:|---:|---:|---:|---:|---:|---:|
| ts-complexity | 1 | 1 | 1.00 | 1 | 0.329 | 7.4 | **4.43%** |

| **aggregate** | **12** | — | — | **1** | **3.259** | **52.3** | **6.23%** |

\* `ts-no-raw-api-calls` briefly double-counted the same files under absolute vs relative keys (adapter vs other sites). Physical parses are at most ~2× per file on that case; parse **time** fraction is unaffected.

## Interpretation (spec D1)

Spec threshold: if parse time is under **~10%** of the run, do not implement a cache.

- Aggregate parse fraction on the M0.A TS golden corpus: **6.23%**.
- Per-case max observed: **10.51%** (one short run; absolute parse time 1.6 ms).
- Observed re-parse multiplicity on this corpus: **≈1** (not the review's “up to 12” estimate). Deep call/value-flow/MIR re-parse sites are not on the capability path for these example rule packs.

## Decision

**ESCALATE** with reason `not-worth-doing` — measured parse cost is a small fraction of run wall-clock on the binding M0.A corpus. Orchestrator may `MERGED-NOOP`; do not invent a per-`FileId` fact cache from this task.
