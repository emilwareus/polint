# W2.3 step 1 — Go RTA dense-id + bitset measurement (mandatory checkpoint)

**Branch:** `swarm/W2.3` @ `5a0f333d` (post-W2.2 integration tip)  
**Date:** 2026-08-08  
**Verdict:** **ESCALATE** — no measurable end-to-end win; wall-clock regresses on the binding synthetic workloads.

## Method

Converted `solve_go_rta` worklists from `BTreeSet<String>` to dense function ids
(qualified-text order) with:

1. `DenseBitSet` for the monotonic reachable set (O(1) membership)
2. `Vec<u32>` frontiers (sparse iteration; avoid O(universe) bit scans)
3. `DenseStamp` for per-round newly-reachable dedup (avoid clearing an O(universe) bitset each round)

Dense adjacency / callsite indexes were rebuilt at the start of each `solve_go_rta` call.
Corpus: synthetic closed `GoRtaInputs` snapshots (same shape as the existing fixpoint unit
tests), timed under `cargo test --release` with warmup + repeated iterations.

W0.A4 golden cost / scale retained-bytes were **not** expected to move from a
fixpoint-local change alone: `GoRtaInputs` still owns the qualified `String` keys in
`roots`, `function_node`, and `static_call_targets`, so AnalysisDb retained bytes stay
dominated by those copies.

## Results (release, same host)

| Workload | Baseline `BTreeSet<String>` | Dense hybrid | Wall-clock |
|---|---:|---:|---|
| Static chain depth 8 000 × 50 iters | **2 479 µs/iter** | 4 477–4 737 µs/iter | **~1.8× slower** |
| Wide fan-out 4 000 callees × 30 iters | **1 094 µs/iter** | 1 939 µs/iter | **~1.8× slower** |

### Worklist-local retained-bytes estimate (N = 8 001 fully reached)

| Structure | Estimate |
|---|---:|
| `BTreeSet<String>` reachable (≈104 B/entry lower bound) | ~832 KB |
| Dense bitset reachable + stamp array | ~1 KB + ~32 KB ≈ **33 KB** |

Local worklist memory improves (~25× on the reachable set), but that saving does **not**
appear in W0.A4 process RSS: the same qualified strings remain live in the input snapshot
for the whole solve, and the fixpoint no longer dominates wall-clock once indexes are
built.

## Interpretation (spec D5)

Spec: if the conversion does not produce a measurable improvement, report ESCALATE — the
model is wrong and the rest of W2.3 should be re-planned.

- Wall-clock: clear regression on both sparse (chain) and wide workloads.
- End-to-end retained bytes / W0.A4 cost: no measured improvement (inputs still hold the
  strings; golden Go examples are far smaller than these synthetics).
- A further attempt to cache dense indexes on `GoRtaInputs` would shrink solve overhead but
  still leave the String-keyed snapshot as the retained-bytes owner; it would not prove the
  StableKeyId migration thesis that step 1 was meant to prove.

## Decision

**ESCALATE.** Do not start StableKeyId / family migration. Hold the whole of W2.3.
Do not assume interning for W2.5.

Product `solve_go_rta` remains the `BTreeSet<String>` worklist (no dense conversion landed);
the dense prototype was measured and discarded.
