# W3.3 — MIR operators, aggregates, closures, place types

**Depends on:** W3.1  
**Binding:** `.swarm/HUMAN-BINDING-2026-08-08-M3-M4.md`

## Goal

Extend statement/value vocabulary so existing Go/TS analyses that currently stuff structure into `Unknown` evidence strings or parallel ASTs can live on MIR:

- `BinOp` / related operator values in `MirValue` or op kinds (match what lowerers already need)
- `Aggregate` construction
- `Closure { body, captures }` with **explicit captures** (this is why `ts_value_flows` forked)
- `PlaceFact` (or successor) records `ty` into the **existing** type lattice — do not invent a second type system

## Done when

- Closure-shaped TS/Go constructs that MIR already attempts to represent use `Closure` with captures.
- Place type field is populated where type facts already exist; consumers can read it without reparsing.
- Goldens + leak gate green.

## Anti-goals

New type lattice. Public SDK changes unless an existing view already promised types. Starting W3.5 fold before Closure exists.
