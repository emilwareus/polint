# W3.1 — `MirBlock` + core terminators

**Tier:** 🔴 design → 🟢 once this spec is followed.  
**Precondition:** tip of `static-analysis-architecture-review` with M2 FactStore / providers.  
**Binding:** `.swarm/HUMAN-BINDING-2026-08-08-M3-M4.md` · [M3-OVERVIEW.md](M3-OVERVIEW.md)

---

## Goal

Make MIR a block-structured IR for Go and TS/JS: every body is a graph of `MirBlock`s ending in a terminator. Emit those from existing MIR lowerers. Teach CFG to build edges from terminators for the **W3.1 terminator set**, and stop using source-text token matching for those shapes.

## Why

`MirStatement` / `MirTerminator` are declared and never constructed (`analysis/mir/body.rs`). CFG `branch_shape` greps source (`cfg/lower_ts.rs` ~244–266, same pattern in `lower_go.rs`). Consumers cannot trust MIR for control flow.

## Design decisions

### D1 — Block model

```rust
pub(crate) struct MirBlock {
    pub(crate) id: MirBlockId,
    pub(crate) body: MirBodyId,
    pub(crate) ordinal: u32,
    pub(crate) statements: Vec<MirStatementId>, // or inline ops — pick one, not both forever
    pub(crate) terminator: MirTerminatorId,
    pub(crate) stable_key: String,
}
```

`MirBody` gains an ordered list of block ids (or blocks live only in `MirOutput.blocks` keyed by body). Prefer **`MirOutput` owns `blocks`, `statements`, `terminators`** alongside existing `operations` **only during migration inside W3.1 PRs** — final W3.1 tip must not require CFG to read flat `MirOperationKind::Branch` for control edges.

### D2 — W3.1 terminator set (construct these)

```rust
pub(crate) enum MirTerminatorKind {
    Goto { target: MirBlockId },
    Branch {
        predicate: MirPredicateId,
        predicate_place: Option<PlaceId>,
        then_target: MirBlockId,
        else_target: MirBlockId,
    },
    Switch {
        discriminant: MirValue,
        cases: Vec<(MirValue, MirBlockId)>, // deterministic order
        otherwise: MirBlockId,
    },
    Return { value: Option<MirValue> },
    Unreachable,
    // Keep Unsupported only as a last-resort escape that W3.2 shrinks
    Unsupported { unsupported: UnsupportedId },
}
```

Replace the current 3-variant stub (`Branch { predicate }`, `Return`, `Unsupported`) — **delete** the old variants; do not keep `Branch { predicate }` without targets.

### D3 — Statements vs operations

W3.1 may keep `MirOperation` rows as the statement payloads (statement → op id) to avoid rewriting every op kind in one PR. Control-carrying ops (`MirOperationKind::Branch`, `Return`) must **stop being the CFG’s source of truth** once blocks exist: either stop emitting them as ops, or emit them only as statement payloads inside blocks with terminators owning edges.

**Brave cut:** prefer terminating forms on `MirTerminatorKind` and keep non-control ops as statements.

### D4 — Lowerers emit structure

`lower_go_mir` / `lower_ts_mir` must construct blocks + terminators for every body they already produce. Incomplete control (today’s `Unsupported` constructs) may still land as `Unsupported` terminators until W3.2 — but **loops and ordinary if/else must not depend on source grepping**.

### D5 — CFG consumes terminators

Shared logic (may still live in two files until W3.4) builds CFG edges from:

| Terminator | Edges |
|---|---|
| Goto | Normal → target |
| Branch | True / False → then / else |
| Switch | SwitchCase / DefaultCase → cases / otherwise |
| Return | → exit |
| Unreachable | none (or edge to unreachable sink — pick one; document in code) |

**Delete** `branch_shape` source-text classification for loop vs conditional once Loop is expressible via back-edges from Goto/Branch targets (structured lowering), or via an explicit `MirTerminatorKind` only if absolutely required — prefer structured blocks with back-edges over a Loop terminator variant.

### D6 — No new languages / no dual production paths

No Python. No second CFG entrypoint. Goldens must pass; if CFG fact shape changes, take the `golden` lock and regenerate with a one-line reason in the land note.

### D7 — SDK / public surface

MIR remains private (`pub(crate)`). `public_surface_leak` must stay green. Do not expose blocks on `RuleCtx`.

## Implementation steps (PR-sized)

1. **Types:** `MirBlockId`, `MirBlock`, expand `MirTerminatorKind` (delete old variants), extend `MirOutput` (+ normalize sort). Unit tests for normalization. Still no production emitters required in this commit **only if** the next commit lands in the same worker session before merge — prefer types+emitters together when gates allow.
2. **Emit:** Update `mir/lower_go.rs` and `mir/lower_ts.rs` so every lowered body has blocks + terminators. Add focused unit tests: if/else → Branch targets; sequential → Goto; return → Return.
3. **CFG:** Switch `lower_{go,ts}_cfg` to walk blocks/terminators for W3.1 kinds. Remove `contains_token` / `operation_evidence` / `source_text` use for branch classification of if/loop/short-circuit **where terminators now encode edges**. Keep construct-string paths only for shapes still `Unsupported` (W3.2).
4. **Cleanup:** Delete dead `MirOperationKind::Branch` control use from CFG if unused; run goldens.

Do not open M4 work from this task.

## Anti-goals

- Do not invent SSA/phi in W3.1.
- Do not add Throw/Suspend/Call-unwind (W3.2).
- Do not delete `cfg/lower_{ts,go}.rs` yet (W3.4) — but do make them terminator-driven.
- Do not add a Python frontend.
- Do not leave flat-op CFG and block CFG both callable from the provider.
- Do not change public SDK fact views.

## Escalate if

- Emitting blocks changes golden diagnostics in a way that cannot be explained as CFG precision change → ESCALATE with samples before mass-regen.
- A MIR body cannot be blocked without parser AST leaking into `mir/body.rs` / `op.rs` → ESCALATE (AST stays in lowerers only).
- Short-circuit / optional-chain cannot be expressed without W3.2 Suspend → leave as `Unsupported` terminator and note in land doc; do not reintroduce source grepping.
