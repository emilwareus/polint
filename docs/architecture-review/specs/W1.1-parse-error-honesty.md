# W1.1 — Parse-error honesty

**Tier:** 🟢. **Precondition:** M0.A green. **This is the only finding that makes the analyzer
*wrong*. Do it early.**

---

## Goal

Never analyse a partial AST without saying so. Every recoverable parse failure must leave a recorded
unknown, so a missing fact is distinguishable from an absent one.

## The defect, stated precisely

Doc 02 describes this as "12 oxc parse sites drop errors." **That framing is imprecise — use this
one instead** (re-verified against the tree):

`crates/polint/src/ts/adapter.rs:489-523` handles parse errors **correctly**. It walks
`parsed.errors`, maps each to a span, and emits a `parser/ts` diagnostic; it also catches the
`panicked && body.is_empty()` case.

Every **secondary** parse site checks only the catastrophic case. Representative — `ts_value_flows.rs:323-330`:

```rust
let parsed = Parser::new(&allocator, file.source.as_ref(),
                         SourceType::from_path(&file.path).unwrap_or_default()).parse();
if parsed.panicked && parsed.program.body.is_empty() {
```

So when a file has a **recoverable** syntax error — `parsed.errors` non-empty but `program.body`
populated — these sites silently analyze a **partial AST** and record nothing.

**Why that is the one unacceptable bug:** the result is a silent under-approximation. Facts are
missing, no unknown marker is emitted, and every downstream consumer treats the result as complete. A
tool whose pitch is honest precision and named unknowns cannot silently under-approximate. It is
strictly worse than failing loudly.

## Design decisions

### D1 — One helper, used everywhere

```rust
/// The only sanctioned way to parse TS/JS in this crate.
pub(crate) fn parse_ts_source<'a>(
    allocator: &'a Allocator,
    file: &SourceFile,
) -> ParsedTsSource<'a>;

pub(crate) struct ParsedTsSource<'a> {
    pub(crate) program: &'a Program<'a>,
    /// Non-empty ⇒ the AST is partial. Consumers MUST record an unsupported fact.
    pub(crate) errors: Vec<ParseError>,
    pub(crate) fully_parsed: bool,
}
```

### D2 — Secondary sites record an unsupported fact, they do not emit a diagnostic

`ts/adapter.rs` already emits the user-facing `parser/ts` diagnostic. Secondary sites must **not**
duplicate it — that would produce N diagnostics for one broken file.

Instead each secondary site records an **`unsupported-semantic fact record`** (the taxonomy already exists and
is already surfaced through `polint inspect unknowns`) noting that its analysis ran on a partial AST.

**Reuse the existing unknown taxonomy. Do not invent a new reason enum.** If no existing variant fits,
escalate rather than adding one unilaterally.

### D3 — Fix `source_type` derivation in the same task

`SourceType::from_path(&file.path).unwrap_or_default()` appears at multiple sites and doc 02 records
two divergent TSX-detection strategies. **Two sites parsing the same file with different options
produce different ASTs**, which is a second silent-divergence bug and a blocker for W1.5's cache key.

Add one `crate::ts::source_type(file) -> SourceType`, route every site through it, delete the copies.

### D4 — Behaviour change, bounded

More `unsupported` facts will be recorded, and `polint inspect unknowns` will report more rows on
repos with broken files. The **diagnostic set must not change** — `ts/adapter.rs` was already emitting
the diagnostics.

Ships as a behaviour PR with regenerated goldens if any golden repo contains a partially-broken file.
If none does, **add a fixture that does** — the absence of such a fixture is part of why this
persisted.

## Implementation steps

1. **Audit and enumerate** every parse site; classify oxc vs tree-sitter, primary vs secondary. Record
   the list in the PR description.
2. **Add `parse_ts_source` + `crate::ts::source_type`** (D1, D3); migrate `ts/adapter.rs` first,
   proving byte-identical behaviour.
3. **Migrate secondary sites**, in batches within the line budget, each recording an unsupported fact.
4. **Add fixtures**: a file with a recoverable syntax error, and one that fails catastrophically.
5. **Audit the Go/tree-sitter sites** separately — tree-sitter is error-tolerant by design and
   produces `ERROR` nodes rather than an error list. Same principle, different mechanism.

## Anti-goals

Do not emit a user-facing diagnostic from secondary sites (D2). Do not add a new unknown-reason
variant without escalating. Do not make parse errors fatal — partial analysis is correct behaviour, it
just has to be *declared*. Do not change tree-sitter sites in the same PR as oxc sites.

## Escalate if

No existing `unsupported-semantic fact record` reason fits · the two TSX-detection strategies turn out to be
intentional · fixing `source_type` changes golden output (that means sites were relying on divergent
parsing — a real finding needing a human decision).
