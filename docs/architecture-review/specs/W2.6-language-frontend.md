# W2.6 — `LanguageFrontend` trait and open `LanguageId`

**Tier:** 🟡 → 🟢 once this spec is read. **Precondition:** W2.4 (`Provider` trait) merged.

---

## Goal

Replace the closed `Language` enum (1,016 references across 129 files) with an open registry, so that
adding a language costs one crate plus one registration line instead of ~19 mandatory edits.

## The fact that makes this safe

**The two adapters already have byte-identical signatures.** Verified:

```
go/adapter.rs:78   pub(crate) fn analyze_with_plan_options_and_cache_stats(
ts/adapter.rs:110  pub(crate) fn analyze_with_plan_options_and_cache_stats(
     db: &mut AnalysisDb, cache: &Cache, config_hash: &str,
     rule_hash: &str, plan: &AnalysisPlan, parallel: bool) -> ProviderAnalysisResult
```

They are called back-to-back by hand at `analysis_kernel/mod.rs:191` and `:209`. **The trait is a
formalization of a contract that already exists in duplicate.**

## Design decisions

### D1 — The trait, with two deliberate generalizations

```rust
pub(crate) trait LanguageFrontend: Send + Sync {
    fn id(&self) -> LanguageId;
    fn handles(&self, path: &Path) -> bool;
    fn profile(&self) -> &'static FrontendProfile;
    fn analyze(&self, ctx: &mut ProviderCtx<'_>, unit: &AnalysisUnit<'_>) -> ProviderRunResult;
}
```

**`FrontendProfile` — declare, don't assume.** Which fact families this frontend produces, and at what
precision. Same shape and purpose as `ProviderManifest.precision_ceiling`:

```rust
pub(crate) struct FrontendProfile {
    pub(crate) produces: &'static [&'static str],      // fact family names
    pub(crate) precision_ceiling: PrecisionCeiling,    // reuse the existing enum
}
```

This lets the planner emit a `polint/capability` diagnostic — "no registered frontend can back
`symbols` for Python here" — instead of running rules on empty facts.

**`AnalysisUnit`, not `&[&SourceFile]`.** A frontend is not necessarily a parser. Writing production
frontends for ten languages is a multi-year project; consuming SCIP / LSIF / LSP / `gopls` / `tsc`
output is not. An index adapter has no AST and different fidelity but can still emit facts.

```rust
pub(crate) struct AnalysisUnit<'a> {
    pub(crate) files: &'a [&'a SourceFile],
    pub(crate) root: &'a Path,
}
```

Today `AnalysisUnit` only wraps the file slice — that is fine. **The point is the shape of the seam,
not extra capability now.** Both generalizations are free today and expensive to retrofit; ship them
in the first version even though nothing exercises them yet. *(This is the one sanctioned exception to
HANDOFF §3 "no abstraction without a caller": the caller is the trait's own two implementations, and
the cost of the wider signature is zero.)*

### D2 — `LanguageId` is opaque, registry-assigned, and NOT a public enum

```rust
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub(crate) struct LanguageId(u16);
```

Assigned by the frontend registry at composition time in registration order.

**Ordering must never be by `LanguageId`.** Same hazard as `StableKeyId` in W2.3 — id order is
registration order, so sorting by it makes output depend on registration. Sort by the frontend's
stable string name. The determinism gate will catch violations; do not weaken it.

### D3 — `Language` survives this task

`Language` is `pub` and in the SDK prelude (`core/mod.rs:184`). Removing it is a **breaking public API
change** and is explicitly out of scope.

- Keep `Language` exactly as it is.
- Add `Language::id(&self) -> LanguageId` and `LanguageId::to_public_language(self) -> Language`.
- Migrate **internal** call sites to `LanguageId` opportunistically.
- The SDK keeps returning `Language`.

Retiring `Language` from the public surface is a separate, later, versioned decision.

### D4 — Collapse the three internal taxonomies, leave the public one

Four parallel language types exist. Three are internal and must collapse into `LanguageId`:

| Type | Location | Disposition |
|---|---|---|
| `Language` | `core/mod.rs:184` | **public — keep** |
| `LanguageTag` | `analysis/identity/facts.rs:30` | → `LanguageId` |
| `LanguageScope` | `analysis_kernel/provider.rs:57` | → `&[LanguageId]` on the manifest |
| `RuleLanguage` | `cli/mod.rs:796` | → `LanguageId` |

`LanguageScope::TypeScriptJavaScript` currently bundles four `Language` variants. Replacing it with a
slice of `LanguageId` is what removes the hardcoded family concept.

### D5 — `is_ts_family()` becomes a frontend-declared family tag

`core/mod.rs:209` `is_ts_family()` has ~49 call sites and does not generalize — "is this in the same
language family" is a frontend property, not a property of a closed enum. Add
`FrontendProfile.family: &'static str`; replace call sites with a family comparison.

**Audit every one of the 49 sites individually.** Some mean "is this JS-like syntax", others mean "use
the oxc parser", others mean "not Go". These are different questions that happen to share an answer
today. Escalate any site whose intent you cannot determine in one sentence.

## Implementation steps — one PR each

1. **Add `LanguageId`, `FrontendProfile`, `AnalysisUnit`, and the trait.** Implement for Go and TS.
   Change `analysis_kernel/mod.rs:191,209` to iterate `&[&dyn LanguageFrontend]`. Golden byte-identical.
2. **`Language::id()` + `to_public_language()`.** No call-site migration yet.
3. **`LanguageTag` → `LanguageId`** (`analysis/identity/`).
4. **`LanguageScope` → `&[LanguageId]`** on `ProviderManifest`.
5. **`RuleLanguage` → `LanguageId`** (`cli/`).
6. **`is_ts_family()` → family tag**, in batches, with the per-site audit from D5.
7. **The acceptance test** (below).

## Acceptance

The task is done when this test passes:

```rust
#[test]
fn adding_a_frontend_touches_only_its_own_module_and_the_registry() {
    // A no-op frontend claiming a fake extension, registered in the host.
    // Assert: it is scheduled, produces zero facts, and emits no diagnostic.
}
```

and a human confirms that adding it required **≤ 2 edits outside its own module** (the module itself,
plus one registration line).

Per PR:
```bash
cargo test -p polint --test golden --locked   # byte-identical
cargo test -p polint --lib eval::determinism_gate --locked
cargo test --workspace --all-features --locked
cargo test -p polint --test public_surface_leak --locked   # SDK surface unchanged
```

Progress metric: `rg -o 'Language::' crates/polint/src --glob '*.rs' | wc -l` trending down from
**1,016**. It will not reach zero — SDK-facing uses are legitimate and stay.

## Anti-goals

Do not remove `Language` or change the SDK surface. Do not make `LanguageId` public. Do not add a
language in this task — the acceptance test's frontend is a no-op stub and must stay one. Do not sort
by `LanguageId`. Do not write a SCIP/LSIF adapter here; W2.6 only makes one *possible* (that is W5.6).

## Escalate if

The public surface leak test goes red · an `is_ts_family()` site's intent is ambiguous · a golden diff
appears · `LanguageScope` turns out to carry semantics beyond "which files does this provider see".
