# W2.5 — `FactStore`: decompose `AnalysisDb`

**Tier:** 🟡 → 🟢 once this spec is read. **Precondition:** W2.4 merged. **Runs after W2.3 or
concurrently with its later families — never on the same fact family at the same time.**

---

## Goal

Turn `AnalysisDb` from a 132-field god struct into a keyed container of provider-owned stores, so a
provider's facts are added and removed with its crate rather than by editing `core`.

## Why

`core/mod.rs:658-825` — 132 fields, essentially all `Vec<…Fact>` or `BTreeMap` indexes, plus
`Option<…Store>` fields. `impl AnalysisDb` is 4,823 lines and 288 methods. Adding an analysis or a
language means editing the file every other module depends on — and the struct includes
language-specific fields (`ts_object_allocations`, `ts_property_writes`, `ts_prototype_links`,
`go_semantic_packages`, `go_semantic_method_sets`, …) in the supposedly language-neutral core.

Nothing is ever dropped mid-pipeline, so the DB only grows.

## The fact that makes this tractable

**Fifteen provider-owned stores already exist** as `Option<T>` fields on `AnalysisDb`:

`semantic`, `call_store`, `identity_store`, `refined_call_store`, `data_flow_store`, `evidence_store`,
`abstract_domain_store`, `summary_store`, `entrypoint_store`, `ts_object_model_store`, `type_store`,
`value_store`, `access_path_store`, `points_to_store`, `alias_store`.

Verify: `awk 'NR>=658 && NR<=825' crates/polint/src/core/mod.rs | grep -oE '[a-z_]+: Option<[A-Za-z]+Store>'`

**The pattern is already established. This task generalizes it to the remaining flat `Vec` fields —
it does not invent it.**

## Design decisions

### D1 — The trait

```rust
pub(crate) trait FactStore: Any + Send + Sync {
    fn family(&self) -> FactFamily;
    fn clear(&mut self);
    fn as_any(&self) -> &dyn Any;
    fn as_any_mut(&mut self) -> &mut dyn Any;
}
```

`AnalysisDb` holds `BTreeMap<FactFamily, Box<dyn FactStore>>` plus typed accessors that downcast.
`BTreeMap`, not `HashMap` — iteration order must stay deterministic.

### D2 — The SDK surface does not change. At all.

Every `sdk/facts.rs` view already holds a private `db` field and exposes `.iter()`. Swapping what is
behind `db` is invisible to rule authors.

**`cargo test -p polint --test public_surface_leak --locked` must pass unchanged at every step. If it goes red, you have
changed a product contract — stop.**

### D3 — Migrate flat `Vec` fields into stores, in provider-ownership groups

Group the 132 fields by which provider writes them. Roughly:

| Group | Fields | Owner |
|---|---|---|
| Source | `files` | `polint.source` |
| Go syntax | `packages`, `functions`, `imports`, `tests`, `branches` | `polint.go.syntax` |
| TS syntax | `ts_components`, `ts_classes`, `string_literals`, `jsx_attributes` | `polint.ts.syntax` |
| Module graph | `module_nodes`, `module_edges`, `resolved_imports`, topology fields | `polint.module_graph` |
| Symbols | `symbols`, `definitions`, `references` + the 5 index maps | `polint.symbol_graph` |
| CFG | the 9 `cfg_*` fields | `polint.cfg` |
| Calls | `call_sites`, `call_targets`, `unresolved_calls` | `polint.calls` |
| … | remaining groups follow the same rule | |

**One group per PR.** Determine ownership from the manifest `outputs`, not by guessing from the field
name.

### D4 — Index maps move with the facts they index

`symbols_by_id`, `definitions_by_symbol`, `references_by_target`, `symbols_by_file`,
`references_by_file`, `symbols_by_name` are derived indexes over the symbol facts. They move into
`SymbolStore` and become its private business. Do not leave them on `AnalysisDb`.

`symbols_by_name: BTreeMap<String, Vec<usize>>` should key on `StableKeyId` **only after** W2.3 has
migrated `SymbolFact` — coordinate; do not do both to the same family at once.

### D5 — Language-specific fields move to their language's store

The `ts_*` and `go_semantic_*` fields move into `TsObjectModelStore` / a new `GoSemanticStore`, owned
by their language's provider. **This is the change that makes `core` language-neutral**, so do not
skip it as cosmetic.

### D6 — Eviction is enabled, not implemented

`FactStore::clear` exists so a later task can drop a store once its consumers have run. **Do not call
`clear()` from the pipeline in this task.** Adding eviction changes what facts rules can see — a
behaviour change, and per HANDOFF §2 rule 2 it belongs in a separate PR with golden justification.

---

## Implementation steps — one PR each

1. **Add the `FactStore` trait, the registry map, and downcast accessors.** Migrate **one** group
   (Go syntax — small, well-bounded) as the proof. Per HANDOFF §3 this lands together, not as a
   trait alone.
2. **One group per PR** for the rest, following D3.
3. **Language-specific fields** (D5).
4. **Delete the now-empty flat fields** and any accessor that existed only to reach them. Doc 02
   records 19 consecutive unused `AnalysisDb` accessors behind `#[allow(dead_code)]` — delete those
   too, and the allows with them.

## Acceptance

Per PR:
```bash
cargo test -p polint --test golden --locked   # byte-identical
cargo test -p polint --test public_surface_leak --locked    # MUST stay green
cargo test -p polint --lib eval::determinism_gate --locked
cargo test --workspace --all-features --locked
```

Cumulative:
- `AnalysisDb` field count 132 → **≤ 30** (verify with the `awk` command in HANDOFF §1)
- Zero `ts_*` or `go_semantic_*` fields on `AnalysisDb`
- `impl AnalysisDb` well under 288 methods
- `rg -c '#\[allow\(dead_code' crates/polint/src/core/` strictly decreasing

## Anti-goals

Do not change fact *contents*, field names, or serialization. Do not add eviction (D6). Do not make
`FactStore` public. Do not use `HashMap` for the registry. Do not migrate a family W2.3 is
concurrently interning. Do not "tidy" a store's internals while moving it — moves are moves.

## Escalate if

The public surface leak test goes red · a field has no clear owning provider, or two providers write
it · a golden diff appears · you find a consumer reading a fact family before its provider runs (that
is a real ordering bug and needs a human decision — ESCALATE, do not work around it).
