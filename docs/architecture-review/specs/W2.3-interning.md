# W2.3 — Intern the identity model (`StableKeyId`)

**Tier:** 🟡 → 🟢 once this spec is read. **Precondition:** W2.2 (`core/mod.rs` split), M0.A green
**including W0.A4 cost records** — this task is judged on memory, so the measurement must exist first.

---

## Goal

Replace `stable_key: String` (229 field declarations) with an interned `StableKeyId(u32)`, and stop
storing the same identity string three times per fact.

## Why — the redundancy, precisely

For each fact admitted to `AnalysisDb`, the same identity string is retained **three times** and the
payload digest **twice**:

| Copy | Location |
|---|---|
| 1 | The fact struct's own `stable_key: String` field |
| 2 | `FactMeta.stable_key` (`analysis_kernel/metadata.rs:229`) |
| 3 | `FactMetaStore.stable_key_owners: BTreeMap<FactFamily, HashMap<String, StableKeyOwner>>` key (`metadata.rs:357`) |
| digest ×1 | `FactMeta.payload_digest` (`metadata.rs:235`) |
| digest ×2 | `StableKeyOwner.payload_digest` |

Keys are human-readable and long — `stable_key_from_parts` (`metadata.rs:465-480`) builds
length-prefixed `family|label=value|…` strings containing repo-relative paths and spans.

**Do not quote "~5.6 KB/LOC" or "66% redundant" as measurements.** They are estimates from struct
definitions. W0.A4 gives you the real number; this task must move *that* number.

## The choke point that makes this tractable

**`stable_key_from_parts` at `metadata.rs:465` is the single *construction* site for stable keys**,
with **115 call sites**. Every key in the system originates there. That is where the interner goes.

There is a second category you must know about: **propagation sites** that take an already-built key
and re-own it, e.g. `stable_key: stable_key.to_string()` at `ts/inventory/store.rs:270,287`,
`ts/object_model/store.rs:442,462-463,481-482`, `cli/mod.rs:4250`. Enumerate them with:

```bash
rg -n 'stable_key[a-z_]*\s*[:=]\s*[a-z_.]+\.to_string\(\)' crates/polint/src --glob '*.rs'
```

These are **not** additional construction sites — they copy a key built elsewhere. They are good news:
once the field type is `StableKeyId`, each becomes a `Copy` instead of a heap allocation. But they are
where the type change bites, so migrate them with their family.

**Net: one function to intern, 115 call sites that keep working unchanged (they receive an id instead
of a String), and a bounded set of propagation sites that get cheaper.** You are not chasing 229
independent decisions.

---

## Design decisions

### D1 — The interner lives in `AnalysisDb`, not a global

```rust
pub(crate) struct StableKeyInterner {
    keys: Vec<Box<str>>,                    // id → text
    ids: HashMap<Box<str>, StableKeyId>,    // text → id
}

#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub(crate) struct StableKeyId(u32);
```

**No process-global interner, no `lazy_static`, no `OnceLock`.** A global would break test isolation
and make the determinism gate meaningless. One interner per `AnalysisDb`, threaded through
`ProviderCtx`.

### D2 — Ordering must be by text, never by id

`StableKeyId` ordering is **allocation order**, which depends on traversal order. Any sort that
currently uses `stable_key` must keep sorting by the *resolved text*, not the id.

**This is the single most likely way to break determinism in this task.** The determinism gate
(10 seeded permutations) will catch it — do not weaken that gate to make a sort pass. Where a hot sort
needs to be fast, resolve to text once into a `Vec<(&str, T)>` and sort that.

### D3 — Migration order, by cardinality

1. `SymbolFact`, `ReferenceFact`, `DefinitionFact` (highest cardinality)
2. MIR: `place-fact record`, `MIR operation`
3. `CallSiteFact`, `CallTargetFact`
4. CFG facts
5. Everything else

**One family per PR.** Each PR must show a measured memory delta from the W0.A4 records.

### D4 — `FactMeta` interning is a separate, later step

Do families 1–5 first, all keeping `FactMeta.stable_key: String`. Only then convert `FactMeta` and
`stable_key_owners`. Reason: `FactMetaStore::insert` (`metadata.rs:362`) uses the key for **conflict
detection**, and conflicts are reported to users with the key text. Changing detection semantics while
also changing 229 field types is two risky things at once.

### D5 — The Go RTA fixpoint is the proof-of-concept, and it goes FIRST

Before touching any fact family, convert the Go RTA fixpoint. It is self-contained and has the
worst instance of the problem:

- `fixpoint.rs:104` — `let mut reachable: BTreeSet<String> = inputs.roots.clone();`
- `fixpoint.rs:112` — `let mut frontier: BTreeSet<String> = inputs.roots.clone();`
- `fixpoint.rs:157` — `let mut newly_reachable: BTreeSet<String> = BTreeSet::new();`
- `inputs.rs:71` — `roots: BTreeSet<String>`
- `inputs.rs:76` — `method_sets: BTreeMap<String, BTreeSet<String>>`

A whole-program fixpoint whose worklist is a `BTreeSet<String>` does string comparison on every
membership test, every round. Convert to dense `SemanticNodeId` indices plus a bitset.

**This is a self-contained PR with a large, measurable win and no cross-cutting risk. It proves the
pattern and gives you a real number before you commit to the migration.** If it does not produce a
measurable improvement, report ESCALATE — the model is wrong and the rest of the task should be
re-planned.

---

## Implementation steps — one PR each

1. **Go RTA fixpoint → dense ids + bitsets** (D5). Report measured before/after.
2. **Add `StableKeyInterner` + `StableKeyId` to `AnalysisDb`.** Nothing uses it yet — but per the
   HANDOFF §3 rule, this must land *with* step 3, not alone.
3. **Route `stable_key_from_parts` through the interner**, returning `StableKeyId`. Add
   `db.resolve_key(id) -> &str`. All existing `String` fields stay, populated via `resolve_key`.
   Golden output byte-identical.
4. **Families 1–5**, one PR each. Field type `String` → `StableKeyId`; call sites resolve at the
   boundary. Golden output byte-identical each time.
5. **`FactMeta` + `stable_key_owners`** (D4). Conflict-detection semantics and user-visible conflict
   messages must be preserved exactly.
6. **Delete `resolve_key` call sites that only existed for compatibility.**

## Acceptance

Per PR:
```bash
cargo test -p polint --test golden --locked   # byte-identical
cargo test -p polint --lib eval::determinism_gate --locked   # 10 seeded permutations
cargo test --workspace --all-features --locked
```

Cumulative, from the W0.A4 records:
- Retained bytes/LOC strictly decreasing, PR over PR
- `rg -c 'stable_key: String' crates/polint/src --glob '*.rs'` trending 229 → 0
- No wall-clock regression on any golden case

## Anti-goals

Do not add an interning crate dependency (`lasso`, `string_cache`, `ustr`) — a `Vec` + `HashMap` is
~40 lines and avoids a semver-coupled dep in a core type. Do not intern anything that is not a stable
key (messages, paths, source text). Do not change key *format* — `stable_key_from_parts`'s output
text must stay byte-identical, because it is persisted in caches and compared across runs. Do not
combine with W2.5.

## Escalate if

The determinism gate goes red · a golden diff appears · step 1 shows no measurable win · you find a
site that compares stable keys by *prefix* or *substring* rather than equality (that would be an
undocumented invariant on the key format and needs a human decision — ESCALATE).
