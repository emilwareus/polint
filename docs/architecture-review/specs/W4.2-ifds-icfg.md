# W4.2 — IFDS/IDE solver over the repaired ICFG

**Depends on:** W3.4 (shared MIR CFG), W4.1 (points-to primary)  
**Binding:** `.swarm/HUMAN-BINDING-2026-08-08-M3-M4.md` · [M4-OVERVIEW.md](M4-OVERVIEW.md)

---

## Goal

Replace unrealizable interprocedural BFS / reachability used by production data-flow / policy path finding with an **IFDS** (or IDE) solver over an ICFG built from:

- MIR-driven CFG (`analysis/cfg/lower.rs`)
- Call edges from the post-W4.1 call graph (direct + points-to-refined)

Call/return matching is mandatory: **no unrealizable path** may be reported by the production path engine this task wires.

---

## Why

`policy_queries` / `data_flow` still assemble paths that can cross call boundaries without return matching. M4 exists to end that. M3 repaired the CFG; W4.1 made call targets honest — now the path engine must match.

---

## Design decisions

### D1 — ICFG from existing facts only

Build an interprocedural CFG view from stored CFG blocks/edges + call sites/targets. Do **not** re-parse source. Do **not** invent a second CFG.

### D2 — IFDS tabulation (minimal viable)

Implement the standard exploded-supergraph tabulation for IFDS:

- Identity / kill / gen flow functions at CFG nodes (enough for taint W4.3; W4.2 may ship with a **boolean reachable-fact** domain first if that is what current path queries need)
- Call-flow, return-flow, and call-to-return flow functions with matched returns
- Worklist fixpoint; deterministic iteration order (`BTree*` / sorted queues)

Prefer one `analysis/ifds/` (or `analysis/ide/`) module owned by the data-flow provider. **Delete** the BFS / unmatched reachability used for the same production queries in the same change — no dual path finder.

### D3 — Wire production consumers

Any production caller that currently builds `DataFlowPath` / policy taint paths via the old reachability must use IFDS results after this lands. Search from `policy_queries.rs`, `data_flow/query.rs`, `data_flow/direct_calls.rs`, slicing interprocedural helpers that feed product diagnostics.

### D4 — No dual

No `legacy_bfs`, no feature flag, no “IFDS then fallback to BFS”. Empty IFDS ⇒ honest unresolved / no path.

### D5 — Scope boundary

- **In:** path engine + ICFG + call/return matching for existing Go/TS flows that already claim interprocedural reachability.
- **Out:** full taint source/sanitizer/sink product rewrite (W4.3), constant-prop IDE lift (W4.5), new languages, new templates.

---

## Implementation steps

1. ICFG builder over CFG store + call targets (unit tests: call then return only to matched caller).
2. IFDS engine with a domain sufficient to reproduce **existing** path-query acceptance tests (start with reachability / data-fact domain already implied by `DataFlowPath`).
3. Switch production path queries to IFDS; delete old unmatched BFS/reachability for those queries.
4. Regression: unrealizable call/return zig-zag must **not** produce a path.

## Anti-goals

Reintroducing recognizer banks. Shipping IFDS unused (R7 / unwired-abstraction). Keeping BFS “for performance.” Public SDK changes. Golden mass-regen without ESCALATE.

## Escalate if

Call graph lacks return edges needed for matching and cannot be derived from existing facts → ESCALATE.  
Golden **diagnostic set** changes → ESCALATE with samples.
