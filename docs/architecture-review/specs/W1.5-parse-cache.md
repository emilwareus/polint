# W1.5 — Per-`FileId` parse cache

**Tier:** 🟡 → 🟢 once this spec is read. **Precondition:** M0.A green **including W0.A4 cost
records** — this task is judged purely on wall-clock, so the measurement must exist first.

---

## Goal

Stop re-parsing the same TypeScript source many times per run.

## Why — and what is actually known

Doc 06 reports 1 parallel plus up to 11 serial full-corpus TS re-parse sites, the worst being
`analysis/calls/ts_value_flows.rs:323` inside a 4-round fixpoint loop.

**Treat "12" as an upper-bound estimate, not a measurement.** Independent greps give different counts
depending on what is being counted (`Parser::new` call sites: 31; files containing
`Allocator::default`: 9). Different metrics, different numbers, all consistent.

**Step 1 is therefore to measure, not to fix.** If the real number is 2, this task is not worth doing
and you should say so.

An important thing that is *already correct* and must not be broken: **ASTs are not retained.** Every
`Allocator` is function-local and dropped at function exit, defended by the invariant comment at
`analysis/calls/js_points_to/provider.rs:60-70` and by regression tests. Peak AST memory is bounded by
(threads × one arena). **The fix is to parse fewer times, never to keep ASTs alive longer.**

---

## Design decisions

### D1 — Measure first; the count decides the design

Add a counter (behind `tracing` at debug level, or a test-only atomic) that records parses per
`FileId` per run. Run it over the M0.A corpus. Report:

- parses per file, max and mean
- total parse wall-clock as a fraction of total run wall-clock

**Then stop and report before implementing.** If parse time is under ~10% of the run, the win is not
there and the task should be re-scoped. This checkpoint is mandatory.

### D2 — Cache the *facts*, not the AST

The tempting design is an arena of live ASTs shared across providers. **Do not do this.** It
converts a bounded memory profile into an unbounded one and breaks the invariant above.

Instead: each parse site is extracting something. Extract once, cache the *derived facts*, and let
later consumers read those. Where two consumers need genuinely different derived data from the same
parse, either merge the extraction or accept the second parse — and record why in a comment.

### D3 — Attack the fixpoint loop first; it is the clearest win

`ts_value_flows.rs:315-368` runs `for _round in 0..MAX_MODULE_SUMMARY_ROUNDS` (= 4) and re-parses
inside the loop. The source **does not change between rounds**. Hoisting the parse out of the loop is
a local, contained change worth up to 4× on that stage alone.

Do this as its own PR before any cross-provider caching.

### D4 — Keep the arena discipline exactly as it is

Whatever you cache must be **owned data with no lifetime tie to an `Allocator`**. If a cached value
borrows from an arena, you have re-introduced AST retention through the back door. The existing tests
that assert no parser AST is stored must keep passing — do not modify them.

### D5 — Byte-identical output, always

Parsing the same bytes twice produces the same facts. If output changes, either the parse sites were
using different parser options (a real latent bug — escalate, do not paper over) or the cache key is
wrong.

**Cache key: `(FileId, content_hash, parser_options)`.** Include parser options — `ts/adapter.rs` has
multiple `source_type` derivations and doc 02 records two divergent TSX-detection strategies (defect
D5). If those disagree, two sites legitimately parse the same file differently, and a key without
options would silently serve the wrong facts.

---

## Implementation steps

1. **Instrument and report** (D1). **Checkpoint — report before continuing.**
2. **Hoist the parse out of the `ts_value_flows` fixpoint loop** (D3). Measure.
3. **Unify `source_type` derivation** (doc 02 defect D5 — one `crate::ts::source_type()`, delete the
   duplicates). This is a prerequisite for a correct cache key.
4. **Add the per-`FileId` fact cache** for the largest remaining duplicate-parse cluster only.
5. **Re-measure.** Stop when the remaining parses are justified and documented.

---

## Acceptance

```bash
cargo test -p polint --test golden --locked   # byte-identical at EVERY step
cargo test --workspace --all-features --locked
```

Plus, from the W0.A4 cost records: **measured wall-clock reduction on the corpus**, reported per step.
No memory regression — peak RSS must not rise, because the whole point is fewer parses, not more
retention.

```rust
#[test]
fn a_file_is_parsed_once_per_distinct_parser_configuration() {
    // Instrumented run over a multi-file fixture.
    // Assert: parses per (FileId, options) == 1.
}
```

## Anti-goals

Do not build a shared AST arena. Do not extend any `Allocator` lifetime. Do not modify the
no-AST-retention regression tests. Do not cache across process runs (that is the store, W5.2). Do not
proceed past step 1 if the measurement says the win is not there — report instead.

## Escalate if

Step 1 shows parse time is a small fraction of the run · two parse sites of the same file produce
different facts (real bug — needs a human decision — ESCALATE) · a golden diff appears · peak RSS rises.
