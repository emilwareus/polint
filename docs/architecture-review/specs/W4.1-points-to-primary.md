# W4.1 — Primary points-to resolver (migrate existing)

**Depends on:** M3 complete (W3.1–W3.5)  
**Binding:** `.swarm/HUMAN-BINDING-2026-08-08-M3-M4.md` · [M4-OVERVIEW.md](M4-OVERVIEW.md)

## Goal

Make the **existing** field-sensitive Andersen / points-to solver (`analysis/points_to`) the **sole** production TS/JS indirect-call resolver path used by refined calls / call graph. Delete recognizer-bank / token / heuristic primary paths that still compete with it. No dual resolver.

## Context after W3.5

`analysis/calls/ts_value_flows.rs` and `analysis/calls/js_points_to` (Oxc reparse frontend) are **gone**. Base calls come from MIR + direct binding; refined edges already mention `ts_js_points_to` tiers in places. Confirm what still selects a non-solver primary path and remove it.

## Design

### D1 — One primary

Production refined-call / call-target resolution for TS/JS must invoke the shared points-to solver (or its already-wired semantic-graph projection). Delete alternate “primary” recognizer banks for the same job.

### D2 — Object sensitivity

Add object sensitivity **only** as required to preserve or restore precision that existing tests/goldens already expect — not a research expansion. Prefer parameters already present in the solver.

### D3 — No dual

No `legacy_resolver`, no feature flag keeping both banks, no “fallback to tokens if points-to empty” that silently reintroduces unrealizable edges. If points-to is empty, report unresolved honestly.

### D4 — Go unchanged except shared plumbing

Do not rewrite Go RTA in this task unless a shared dispatch forces a touch; keep Go on its existing RTA policy.
